## Accomplishments

### Task 1 — the record shape and the six constants (`534882d`)

**`name` on all five `DEFAULTS.tokens` records.** `hp` -> `Health`, `ap` -> `Action points`,
`shield` -> `Shield`, `dmg` -> `Damage`, `dead` -> `Dead marker`. One edit covers three call
sites, because `defaults()` is a JSON deep copy of the frozen literal and `resetToDefaults`
reuses `defaults()`. The key stays the identity (D-09): `hp`, `ap`, `shield`, `dmg` and `dead`
are load-bearing in `[S02]`, `[S05]` and `[S06]`, so a rename touches the label and nothing else.

**Six new module-scope constants**, declared beside `SHAPES` / `COLORS` / `TOKEN_IDS` and added
to the frozen `[S01]` export literal in declaration order:

| Constant | Value | Why this value |
|---|---|---|
| `TOKEN_ID_PATTERN` | `/^t[0-9]{1,2}$/` | Research measured that `^[a-z][a-z0-9]{0,7}$` admits `apply`, `bind`, `call`, `caller`, `length` and `name`. This one admits **none** of the twenty names reachable from `Object.prototype` or `Function.prototype`. The leading `t` also keeps `Object.keys` in insertion order — an integer-like key sorts first and numerically, which would silently reshuffle a vocabulary a positional Phase 4 codec depends on. |
| `RESERVED_KEYS` | frozen `['__proto__','constructor','prototype']` | The **message**, not the defence. The pattern is what keeps these out; this list is what lets the refusal name what it refused (D-14). |
| `MAX_CUSTOM_TYPES` | `6` | D-18. A Phase 4 dial, exactly as `--tok` was a rehearsal dial for Phase 2. |
| `TOKEN_SCOPES` | frozen `['unit','side']` | D-01. Carries the same append-only-never-reorder banner `GLYPHS` carries, because Phase 4 may encode a scope positionally. |
| `MAX_TOKEN_NAME` | `24` | D-12. The unit is **code points**, not UTF-16 units, and the comment says so. |
| `TOKEN_NAME_REFUSE` | `/[\p{Cc}\p{Cs}]/u` | Refuses control characters and lone surrogates and **nothing else**. Names may carry BMP symbols and emoji (D-12). |

The `TOKEN_NAME_REFUSE` comment records the override explicitly: `02.1-RESEARCH.md` § Pattern 3
proposed `/^[A-Za-z0-9 ,.'!?()-]{1,24}$/`, and D-12 is the user's later decision the other way.
`grep -c "A-Za-z0-9 ,\.'" cats-vs-mechs.html` returns **0** and is a standing regression check.

### Task 2 — the five guards, and `setTokenStyle` moved onto them (`9437f0b` RED, `8df8725` GREEN)

**RED (`9437f0b`):** the `[S09.7]` rows were written first against guards that did not exist.

**GREEN (`8df8725`):** **188 passed / 0 failed**, interaction gate 27 of 27.

Five pure, DOM-free, `App.state`-free guards were added beside `requireSide`, every one of them
called **outside** every commit (Pitfall 10 — a refusal must leave no phantom undo step over a
board that never changed), and every one using `String(x)` inside its message so a symbol or an
object cannot throw while the error is being built:

| Guard | Contract |
|---|---|
| `requireTokenId` | non-string -> `RESERVED_KEYS` by name -> early return for a built-in -> pattern. **That order is load-bearing.** |
| `requireNewTokenId` | refuses a built-in id first, then delegates to `requireTokenId` |
| `requireTokenName` | `trim()` FIRST, then empty, then `Array.from(...).length` against the cap, then `TOKEN_NAME_REFUSE`. Returns the trimmed string. |
| `clampTokenName` | `Array.from(String(raw)).slice(0, MAX_TOKEN_NAME).join('')`. Never throws. |
| `nextTokenTypeId` | scans `Object.keys`, takes the largest suffix in use and adds one; refuses at `t99` |

**`setTokenStyle` was rewired, not widened.** Its opening
`if (App.data.TOKEN_IDS.indexOf(tokenId) === -1) { throw ... }` is gone and replaced by
`requireTokenId(tokenId)` followed by a `hasOwnProperty` existence check against the live
vocabulary. Without that second check `setTokenStyle('t7', ...)` would pass the pattern and then
die inside the mutator as "cannot read properties of undefined" — the nameless failure style
`requireSide` exists to prevent. The value guards, the no-op-returns-`false` block and the
field-by-field mutator are untouched. Every `[S09.6]` row survived the change: `sparkle` fails
the pattern, `__proto__` and `constructor` fail the named list.

## Both corruption shapes, gated and proven

ROADMAP criterion 5 is a **security** criterion, and research measured **two** distinct shapes.
Both are gated, and each has its own assertions per reserved key.

| Shape | How it corrupts | Where it is refused | Assertions |
|---|---|---|---|
| **CREATE** — `tokens[id] = rec` | Invokes the `__proto__` setter and **reparents** the vocabulary. Own keys, `JSON.stringify` and `deepFreeze` all read green, and it evaporates on the next `thaw()`. | `requireNewTokenId` -> `requireTokenId`'s `RESERVED_KEYS` branch, before any commit is entered | 3 x `t.throws` + 3 x message-names-the-key + `Object.getPrototypeOf(build.tokens) === Object.prototype` |
| **RENAME** — `var rec = tokens[id]; rec.name = x` | Resolves `rec` to `Object.prototype` and writes onto it. **Persistent, global, and invisible to `JSON.stringify` and `deepFreeze` alike.** The CR-02 shape exactly. | `setTokenStyle` -> `requireTokenId`, then the `hasOwnProperty` existence check | 3 x `t.throws` + 3 x `({}).shape === undefined && !Object.prototype.hasOwnProperty.call(Object.prototype, 'shape')` |

A row per key rather than one row total, because `'constructor'` fails with a **different**
`TypeError` than `'__proto__'` does, so a single case does not cover the class.

## Red-then-green: the gate observed to fail, three times

The plan asked for one probe: skip `requireTokenId`'s `RESERVED_KEYS` branch and confirm rows 4
and 5 go red. **That probe does not go red, and the reason is worth recording** — the gate turned
out to have three independent layers, each of which alone refuses all three reserved keys. So the
probe was run three times, peeling one layer per run, until real `Object.prototype` pollution was
actually observed.

| Run | What was removed | Result | What it proves |
|---|---|---|---|
| **Baseline** | nothing | **215 passed, 0 failed** | — |
| **R1** | `requireTokenId`'s `RESERVED_KEYS` branch (`if (false)`) | **215 passed, 0 failed** | Layer 2 alone holds: `TOKEN_ID_PATTERN` refuses all three keys, and its message still names the refused text. The named list is the *message*, exactly as its comment claims. |
| **R2** | the whole of `requireTokenId` (`return tokenId;` as the first statement) | **194 passed, 21 failed** | The CREATE-shape rows (row 4, all six) go **red**, along with every `requireTokenId` refusal row. Layer 3 — `setTokenStyle`'s `hasOwnProperty` check — still holds the RENAME shape. |
| **R3** | `requireTokenId` **and** `setTokenStyle`'s existence check | **183 passed, 32 failed** | The RENAME-shape rows go **red**, including `and nothing leaked onto the shared object prototype through __proto__` — i.e. the assertion **observed real global `Object.prototype` pollution**, which is the evidence the plan was asking for. `[S09.6]`'s own `nothing leaked onto the shared object prototype` row went red too. |
| **Restored** | — (`git checkout -- cats-vs-mechs.html`) | **215 passed, 0 failed**, exit 0 | Green again. |

The finding for later plans: the id gate is **defence in depth**, not a single check. Plan 02.1-02
must apply all three layers to `createTokenType`, `renameTokenType`, `removeTokenType`, `setTally`
and `nudgeTally`, not just the named list, or it will inherit a defence that reads correct and is
one layer thin.

## Deviations from Plan

### 1. [Scope boundary] `grep -c "TOKEN_IDS.indexOf(tokenId) === -1"` returns 1, not 0

- **Found during:** Task 2 acceptance
- **Issue:** the plan's acceptance criterion expects **0**, on the assumption that
  `setTokenStyle` held the only occurrence. It did not. A second one lives in
  `[S06.2] picker()` — `var id = (App.data.TOKEN_IDS.indexOf(tokenId) === -1) ? App.data.TOKEN_IDS[0] : tokenId;`
  — a render-side fallback that substitutes `hp` when the picker is asked for an unknown type.
- **Resolution:** **not changed.** A scoped check proves the criterion's actual intent is met:
  `awk '/^  function setTokenStyle/,/^  \}/' cats-vs-mechs.html | grep -c "TOKEN_IDS.indexOf"`
  returns **0**. The surviving occurrence belongs to plan **02.1-02**, which replaces the picker
  outright with the list-plus-editor (D-05) and owns that fallback's fate. It is unreachable with
  a custom id today because no create op exists yet and the topbar only offers the five built-ins.
  Editing a render path in a plan whose stated output is "a board that behaves identically to
  today" would have risked the 27-of-27 interaction gate for no behavioural gain.
- **Carried forward:** plan 02.1-02 must delete or re-gate `[S06.2] picker()`'s fallback, or a
  student will be able to create a type and then be shown the Health editor when they select it.
- **Files modified:** none
- **Commit:** n/a
