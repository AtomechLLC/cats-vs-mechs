### Locked Decisions

Copied verbatim. **D-01 through D-18 are decided. Research below answers HOW, never WHETHER.**

**Locked upstream — do not re-litigate**

- **D-00a:** Tokens are data — `{ shape, color, glyph }` per type — and the renderer is already vocabulary-driven. This phase adds fields to that record; it does not change the approach.
- **D-00b:** Every emoji pairs with a shape and colour that carry the meaning on their own. Emoji render from OS-supplied fonts and will not match across a classroom.
- **D-00c:** Token appearance lives in the `build` slice, so every change here is undoable through `commit` (not `commitUi`). New types and their tallies inherit this for free.
- **D-00d:** The glyph set is curated, not free text — measured at 12–30 chars per emoji against Phase 4's 512-char budget.
- **D-00e:** A student-created token **counts nothing on its own**. It carries a tally the student increments by hand. The tool tracks the number and never infers what it means. *(User's decision, taken when this phase was created.)*

**Where a custom token's tally lives**

- **D-01:** **The student chooses the scope when creating the type — per-unit or per-faction.** The ROADMAP criterion says "per-unit or per-faction" and left it open deliberately. Both patterns already exist on the board: `hp` and `shield` are per-unit, `ap` is per-faction. Forcing one would make half of plausible student inventions awkward — "poison on *that* cat" is per-unit, "objective markers" is per-faction.
- **D-02:** **This is cheap specifically because both render sites already exist.** `[S06]` already renders a faction-level quantity at `side + '/ap'` and per-unit quantities in the unit card rows. A scoped custom type reuses whichever insertion point its scope names. Adding one `scope` field to the type record buys real flexibility without inventing a new layout.
- **D-03:** **Scope is fixed at creation and cannot be changed afterwards.** Changing it would orphan every tally already recorded under the old scope, which needs migration semantics nobody will remember at a workshop. Removing the type and creating a fresh one is the supported path, and the tallies are trivially re-entered.
- **D-04:** **Tallies default to zero and are stored sparsely.** A type that has never been incremented on a given unit stores nothing. This matters for Phase 4: 9 Cats × 6 custom types is 54 potential numbers, and almost all of them will be zero in a real build.

**Reaching the editor**

- **D-05:** **Collapse the four topbar buttons into one "Tokens" button.** Today `#topbar` carries four `openTokenPicker` buttons, one per built-in type. That does not survive students inventing types — the bar grows without bound, on a projector, which is the one place UX-02 says it must not. One button opens the picker; the picker shows **every** type, built-in and custom, as a selectable list with the editor beside it, plus a "New token type" affordance. This bounds the topbar at one button permanently and solves reachability for custom types properly rather than bolting a second mechanism onto the board.
- **D-06:** ⚠️ **Needs user confirmation.** D-05 changes UI that Phase 2 shipped and a human approved. The four separate buttons are gone, replaced by one. The behaviour is strictly better and the phase is closed rather than frozen, so this is legitimate forward work — but it *is* a visible change to something already signed off, so the planner should surface it rather than let it arrive as a surprise at the next rehearsal.
- **D-07:** **A shipped test asserts the old count and must be updated in the same plan that changes the topbar.** `grep -c 'data-act="openTokenPicker"'` currently returns 4 by design, and `02-03`'s acceptance record names that number. When 02.1-02 collapses the buttons, that assertion goes red. **That is the gate working, not a regression** — update it in the same commit, and do not "fix" it by leaving the four buttons in place.
- **D-08:** **No board-side edit control.** Phase 2 established this (duplicate `data-k` values on the board would break `withPreservedFocus`'s first-match restore). Custom types do not get an exception.

**What a name means**

- **D-09:** **The name is a display label. The id remains the identity and is never shown.** `hp`, `ap`, `shield`, `dmg` and `dead` are load-bearing in `[S05]`, `[S06]` and the model — a rename must not touch them.
- **D-10:** **Built-in types can be renamed.** A student calling Health "Vigor" is exactly the authorship this phase is for, and it changes the label and nothing else.
- **D-11:** **Names need not be unique.** Two types called "Poison" are confusing but not corrupting, since the id disambiguates. Enforcing uniqueness would add a validation path and an error message for a harmless case; a workshop tool should spend its error messages on things that actually break.
- **D-12:** **Names are capped at 24 characters and restricted to a printable allowlist.** The name rides in the Phase 4 build code, so an unbounded string is a budget hole and an injection surface. The cap is a Phase 4 tuning dial, like `--tok` was for Phase 2.
- **D-13:** **A new type's id is produced, never derived from its name.** Deriving an id from user text reintroduces exactly the collision-and-prototype-key problem criterion 5 exists to prevent. Produce it from a monotonic sequence (`t1`, `t2`, …) — see the naming trap in `<code_context>` before writing that code.
- **D-14:** **Id validation replaces membership validation, and must still refuse by name.** `TOKEN_IDS` is currently a frozen five-item allowlist, and that allowlist *is* the CR-02 prototype-pollution defence. Opening the id space means validating the *shape* of an id instead (a short lowercase-alphanumeric pattern), and explicitly refusing `__proto__`, `constructor`, `prototype` and collisions with the five built-ins — with a message naming what was refused, not a silent drop. This is ROADMAP criterion 5 and it is a security criterion, not a polish one.

**Removal and its blast radius**

- **D-15:** **The five built-ins cannot be removed.** The rest of the board binds to them. Attempting it is refused by name, same as an invalid id.
- **D-16:** **Removing a custom type removes its tallies with it, as one undo entry.** Ctrl+Z restores the type and every tally together. This falls out of D-00c for free.
- **D-17:** **No confirmation dialog on removal.** Because D-16 makes it a single undoable step, a modal would cost an instructor a click mid-demo to protect against something Ctrl+Z already covers. Contrast reset-to-defaults, which Phase 4 *does* confirm — that one is broad and destructive; this one is narrow and reversible.
- **D-18:** **Cap custom types at 6, and treat the cap as a Phase 4 dial.** Six types at roughly 30 chars of definition each is ~180 chars before any tallies, against a 512-char design target that already carries the roster. Ships at 6; Phase 4 owns re-tuning it against measured codec output, exactly as `--tok` ships as a rehearsal dial for the projector.

## Summary

The phase is smaller than it looks in three places and larger than it looks in two.

**Smaller than it looks.** The renderer is already vocabulary-driven, so a custom type needs *one* new branch in `amountFor` and *one* builder loop — `styleFor`, `makeToken`, `safeShape`, `safeColor` and `syncRow` all handle an unknown token id today with zero changes, and `COMPACT_AT = 12` applies to a custom tally for free (measured: a row at 12 renders `12×` + one token regardless of which type it is). The tally state shape that works is the *nested* one — `unit.tally = { t1: 3 }` and `faction.tally = { t2: 5 }` — and it passes all **145** shipped assertions unchanged, because it adds no top-level `build` key. And `commitStructural` already exists as the "this changes what `structure()` would build" funnel, so create and remove of a *type* need no new mechanism.

**Larger than it looks.** First, the security criterion has **two distinct corruption shapes, not one**, and only one of them is the CR-02 shape the file already documents. A *create* op (`tokens[id] = rec`) with `id === '__proto__'` silently **reparents the vocabulary** — own keys unchanged, `JSON.stringify` unchanged, `deepFreeze` still reporting frozen, and the whole thing evaporating on the next unrelated commit's `thaw()`. A *rename* op (`var t = tokens[id]; t.name = x`) with the same id resolves `t` to `Object.prototype` and writes **global prototype pollution** that `JSON.stringify` and `deepFreeze` both walk straight past. Both were executed; both are invisible to every gate in the repo. Second, the shipped picker's repaint gate is `dlg.dataset.sig === id + '/' + shape + '/' + color + '/' + glyph`, which **does not spell the name and does not spell the vocabulary's membership** — measured, a rename and a whole new type both left the open dialog completely unmoved. Any list-plus-editor built on that signature is born broken.

The naming trap is unusually live here: `"generating an id"` trips the acceptance grep (gene-**rating**) while `"generated id"` does not — verified mechanically against both greps, along with `iterating`, `operating`, `separating`, `enumerating`, `decorating` and `encounter`.

**Primary recommendation:** In 02.1-01, add `name` to every vocabulary record and `scope` to custom ones, store tallies nested at `build[side].units[i].tally` / `build[side].tally` (never a new top-level `build` key), and replace `TOKEN_IDS` membership with a **two-layer gate** — a produced-id pattern `^t[0-9]{1,2}$` narrow enough that no `Object.prototype` name can match it, *plus* an explicit named refusal list — with every guard outside the commit, exactly as `setTokenStyle` already spells it. In 02.1-02, replace the picker's signature with a JSON fingerprint of the whole drawn vocabulary, keep the selected id in `dlg.dataset.tok` instead of parsing it out of the signature, and put the name `<input>` in the static dialog markup so the per-frame repaint can skip it the way `setValue` already skips a focused field.

### Alternatives Considered

| Instead of | Could use | Tradeoff — and the measurement |
|------------|-----------|--------------------------------|
| A plain object keyed by student ids | `Object.create(null)` bag | **Does not survive the funnel.** `thaw()` is `JSON.parse(JSON.stringify())`; a null-prototype bag committed in one mutator comes back with `Object.prototype` on the *next* commit. Executed: `right after the commit → null-proto`, `after one more commit → Object.prototype`. It buys one commit of safety and then silently stops. **Reject.** |
| A plain object | `Map` | **Silently emptied.** `JSON.stringify(new Map([...]))` is `"{}"`. Executed: a `Map` committed into `build.tokens` was `{}` after the next thaw, with no error anywhere. `[S03]`'s banner promises exactly this ("anything that is not JSON-clonable disappears loudly") — except it disappears *quietly*. **Reject.** |
| A plain object + a name gate | A plain object + `hasOwnProperty` on every read | Necessary but **not sufficient**, and the file already does it in `styleFor`. It protects reads; the corruption in Pitfall 1 and 2 is on the **write**. Do both. |
| Nested tallies (`unit.tally`) | A new top-level `build.tally` bag | **Turns a shipped assertion red.** Measured: `state contract :: the board has its build keys` fails, 144/1. That assertion is a *shape* assertion whose own comment anticipates growth ("Phase 4's codec work may well add another key"), so updating it is legal — but it is a needless change to a Phase 1 contract when the nested shape passes 145/0 untouched. **Prefer nested.** |
| An id pattern of `^[a-z][a-z0-9]{0,7}$` | The narrower `^t[0-9]{1,2}$` | Measured: the generic lowercase pattern **admits** `apply`, `bind`, `call`, `caller`, `length`, `name`. None of those is dangerous on a plain-object bag (they live on `Function.prototype`), but the narrow pattern admits **none** of the 20 inherited names at all and matches D-13's produced-sequence decision exactly. **Take the narrow one, and keep the named refusal list anyway** for message quality and for Phase 4's paste path. |

## Project Constraints (from CLAUDE.md)

Every one of these is a hard gate; a recommendation violating one is worthless. Restated here so the planner can check tasks against them without a second read.

1. **One self-contained HTML file, one classic `<script>`, one `<style>`.** No build step, no dependencies, no runtime network. Opens by double-click from `file://`.
2. **No markup-parsing sink anywhere**, including inside comments: `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `srcdoc`, `DOMParser`, `createContextualFragment`, `eval`, `Function(`. All page text via `createElement` + `textContent`. Enforced document-wide by `tests/selftest-node.cjs` section 1.
3. **No `https?://` anywhere in the file** — which is why there is no inline SVG (`createElementNS` needs the namespace URL) and why shapes are CSS `clip-path:polygon()`.
4. **No `fetch` / `XMLHttpRequest` / `<link>` / ` src=` / `@import` / `url(` / `<iframe>` / `javascript:` / `type="module"`.** All in the same scan.
5. **Combat resolution is deliberately not automated.** A custom token counts nothing on its own; the tool never infers what one means.
6. **Derived values are computed during render, never stored in state.** A stored derivation is a second, mechanical reason for the projection to disagree with the board.
7. **Readability is deliberate.** No minification, no extraction, no helper placed next to its caller instead of in its section.
8. **Namespaced IIFE per section returning `Object.freeze({...})`;** cross-section references resolved at call time as `App.x.y()`, never captured at section-body scope.
9. **`commit` vs `commitUi` are the two greppable write paths.**
10. **GSD workflow enforcement:** no direct repo edits outside a GSD command.

### Pattern 1 — the id gate (02.1-01, ROADMAP criterion 5)

**What:** Two layers — a produced-id *pattern* narrow enough that no inherited name can match, plus an explicit *named* refusal list. Both, not either.

**Why two:** the pattern is the real defence and the list is the *message*. D-14 requires the refusal to name what was refused. A student who somehow reaches `__proto__` deserves "that name is reserved by JavaScript itself", not "an id must look like t1".

**When to use:** every entry point that indexes `build.tokens` with a caller-supplied key — `createTokenType`, `renameTokenType`, `removeTokenType`, `setTally`, `nudgeTally`, and (Phase 4) the decoder. `setTokenStyle`'s existing `TOKEN_IDS.indexOf` check must be replaced with the same gate, or a restyle of a custom type is impossible.

```javascript
// [S01] DATA — beside SHAPES / COLORS / TOKEN_IDS, and exported for the same
// reason they are: [S05] and [S09] assert against the constant.

// The five the rest of the board binds to. Renamed, never removed (D-15).
var TOKEN_IDS = deepFreeze(['hp', 'ap', 'shield', 'dmg', 'dead']);

// A student-made type's id is produced from a sequence, never derived from the
// name they typed (D-13). The pattern is deliberately narrower than "lowercase
// alphanumeric": a generic pattern admits apply, bind, call, caller, length and
// name, all of which are inherited property names. This one admits none of the
// twenty names reachable from Object.prototype or Function.prototype, so the
// list below is a message rather than the defence.
var TOKEN_ID_PATTERN = /^t[0-9]{1,2}$/;

// Refused BY NAME so the student reads a sentence instead of a pattern.
var RESERVED_KEYS = deepFreeze(['__proto__', 'constructor', 'prototype']);

var MAX_CUSTOM_TYPES = 6;                      // D-18, a Phase 4 dial
var TOKEN_SCOPES = deepFreeze(['unit', 'side']);   // D-01, fixed at creation (D-03)
```

```javascript
// [S05] OPS — the shape setTokenStyle already uses: the KEY is checked before
// anything indexes state, and every guard runs OUTSIDE the commit so a refusal
// leaves no phantom undo step over a board that never changed.

function requireTokenId(tokenId) {
  if (typeof tokenId !== 'string') {
    throw new Error('A token type has to be named by text, not by ' + typeof tokenId + '.');
  }
  if (App.data.RESERVED_KEYS.indexOf(tokenId) !== -1) {
    throw new Error('"' + tokenId + '" is a name JavaScript reserves for itself, '
      + 'and using it would corrupt the board. Pick another.');
  }
  if (App.data.TOKEN_IDS.indexOf(tokenId) !== -1) { return tokenId; }   // a built-in
  if (!App.data.TOKEN_ID_PATTERN.test(tokenId)) {
    throw new Error('"' + String(tokenId) + '" is not a token type on this board.');
  }
  return tokenId;
}

// The extra half a CREATE needs: a built-in id may be styled and renamed, but
// never re-created, and never removed (D-15).
function requireNewTokenId(tokenId) {
  if (App.data.TOKEN_IDS.indexOf(tokenId) !== -1) {
    throw new Error('"' + tokenId + '" is one of the five token types the board is '
      + 'built on, so it cannot be re-used for a new one.');
  }
  return requireTokenId(tokenId);
}
```

**The sequence** (D-13 — and note the naming trap: write *produced*, never *generating*):

```javascript
// Scan the live vocabulary and take the largest suffix in use, plus one. The
// same shape nextUnitId already uses, and for the same reason: prefix + count
// collides after any removal, and a duplicate token id is silent in every
// direction at once.
function nextTokenTypeId(vocab) {
  var highest = 0;
  Object.keys(vocab).forEach(function (id) {
    var m = /^t([0-9]{1,2})$/.exec(id);
    if (m !== null && Number(m[1]) > highest) { highest = Number(m[1]); }
  });
  if (highest >= 99) { throw new Error('This board has run out of token type slots.'); }
  return 't' + (highest + 1);
}
```

**Executed evidence.** `p5.cjs` ran the validator against 21 inputs including `t1`, `t12`, `t100`, `hp`, `__proto__`, `constructor`, `prototype`, `toString`, `valueOf`, `''`, `'T1'`, `'t1 '`, `'t1\n'`, `'1'`, `5`, `null`, `{}`. Only `t1`, `t12` and `t0` were accepted. Two details worth knowing: JS `$` does **not** match before a trailing newline the way Perl's does, so `'t1\n'` is refused (verified, not assumed); and `t0` is accepted by the pattern but is never produced by the sequence — harmless, and refusing it would cost a branch for nothing.

### Anti-patterns to avoid

- **Validating the value but not the key.** `setUi` and `setTokenStyle` both carry a comment explaining why; CR-02 is the incident. A patch-merge helper (`Object.assign(t, patch)`) is the exact shape that slips a prototype key past a value-only allowlist — `setTokenStyle`'s mutator spells the three fields out one at a time for precisely this reason. Do the same for `name` and `scope`.
- **Deriving the id from the name.** D-13. `slugify('__proto__')` is `__proto__`.
- **A bare `vocab[id]` read.** Measured: `vocab['constructor']` and `vocab['toString']` both resolve to functions on a perfectly ordinary object. `styleFor` already uses `hasOwnProperty`; every new read must too.
- **Storing whether a type is custom.** `isCustom(id)` is `App.data.TOKEN_IDS.indexOf(id) === -1` — a derivation, computed at use. A stored `custom: true` is a second source of truth that can disagree with the id.
- **Letting `dispatch` grow a UI arm.** `openTokenPicker` is deliberately absent from `[S05]` and a must-not-regress grep (`case 'openTokenPicker'` = 0) enforces it. `selectTokenType` belongs in `UI_ACTS` for the same reason.

### Pattern 2 — sparse tallies, nested (02.1-01, D-01/D-04)

**What:** a tally bag hangs off the record that owns the scope. Nothing at all is stored for a zero.

```javascript
// build.cats.units[0]  — a unit-scope tally
{ id: 'c1', name: 'Cat 1', maxHp: 3, shield: 0, tally: { t1: 2 } }

// build.cats             — a side-scope tally
{ id: 'cats', name: 'Cats', ap: 3, units: [...], actions: [...], tally: { t2: 3 } }

// build.tokens           — the vocabulary
{
  hp:     { shape: 'sq',   color: 'green',   glyph: '',  name: 'Health' },
  ap:     { shape: 'tri',  color: 'gold',    glyph: '',  name: 'Action points' },
  shield: { shape: 'sq',   color: 'accent',  glyph: '',  name: 'Shield' },
  dmg:    { shape: 'dia',  color: 'coral',   glyph: '',  name: 'Damage' },
  dead:   { shape: 'rect', color: 'ink-dim', glyph: '💀', name: 'Dead marker' },
  t1:     { shape: 'circ', color: 'violet',  glyph: '',  name: 'Poison', scope: 'unit' }
}
```

**Two rules make it sparse and keep it so:**
1. A tally of zero **deletes its key**. A bag with no keys left **deletes itself**.
2. `addUnit` never copies `tally` from the seed unit. (`addUnit` already copies `maxHp` and `shield` field-by-field from `last`, so this is a rule about *not* adding a line, which is the easiest kind to get wrong later — assert it.)

```javascript
function tallyBag(owner, create) {
  if (!Object.prototype.hasOwnProperty.call(owner, 'tally')) {
    if (!create) { return null; }
    owner.tally = {};
  }
  return owner.tally;
}

function writeTally(owner, tokenId, n) {
  if (n === 0) {
    var bag = tallyBag(owner, false);
    if (bag === null) { return; }
    delete bag[tokenId];
    if (Object.keys(bag).length === 0) { delete owner.tally; }   // rule 2
    return;
  }
  tallyBag(owner, true)[tokenId] = n;
}

function readTally(owner, tokenId) {
  if (!owner || !Object.prototype.hasOwnProperty.call(owner, 'tally')) { return 0; }
  return Object.prototype.hasOwnProperty.call(owner.tally, tokenId) ? owner.tally[tokenId] : 0;
}
```

**Executed evidence — this is the finding the planner most needs.** `p6.cjs` committed each candidate shape into the live board and then ran the artifact's own suites:

| Shape | `Object.keys(build)` | `allIntegers` | JSON-clonable | Shipped suite |
|---|---|---|---|---|
| baseline | `schema, cats, mechs, tokens` | ✓ | ✓ | **145 / 0** |
| **nested `unit.tally` + `faction.tally`** | `schema, cats, mechs, tokens` | ✓ | ✓ | **145 / 0** |
| new top-level `build.tally` | `…, tokens, tally` | ✓ | ✓ | **144 / 1** — `state contract :: the board has its build keys` |
| `name` on all five built-ins | unchanged | ✓ | ✓ | **145 / 0** |

The nested shape is the only one that costs nothing. `allIntegers` (`[S09.3]:3592`) walks `Object.keys` recursively and permits strings, so `name` and `scope` pass; the integers in the tally bags pass; and `[S09.1]`'s `'the vocabulary survives the integer walk'` row keeps its meaning.

**Undo (D-16) is free.** `removeTokenType` deletes the vocabulary entry *and* walks both sides deleting the id from every bag, inside one `commitStructural` mutator ⇒ one snapshot ⇒ one Ctrl+Z. Nothing extra is needed.

**Unit removal is free too.** `removeUnit` splices the unit object; its `tally` goes with it.

**The one asymmetry to write down:** `sideFromBuild` (`[S05]:1213`) copies `{id, hp, shield, alive}` explicitly, so **tallies do not enter the fight slice.** That is correct for this phase — a build-time annotation — and it is Phase 5's decision whether a tally should be spendable during a fight. Say so in a comment rather than leaving the next reader to wonder whether it was missed. It is the same "the field ships now, its writer arrives with the phase that has a surface" precedent `shield` and `log` already set.

### Pattern 3 — the name field (02.1-01 validation, 02.1-02 surface, ALLOC-10 / D-12)

**Do not reuse the numeric field machinery.** `isField(el)` is `classList.contains('stp-field')`, and everything downstream — `parseField`'s `/^([+-]?)(\d{1,3})$/`, `FIELD_OPS`, `showFieldValue` — is numeric by construction. A name field carrying `.stp-field` would have "Poison" parsed as a number and refused on Enter.

**Do reuse the *pattern*:** a `dataset.was` baseline recorded on focus, Enter commits loudly, Escape reverts, blur commits quietly. That is four small functions, and `commitField`'s own `el.value === el.dataset.was` early return is the guard that stops Enter-then-blur applying twice — copy it.

**The allowlist — recommended, with the measurement behind it:**

```javascript
// [S01] DATA
// Letters, digits, space and eight punctuation marks. Deliberately ASCII:
//   - the name rides in the Phase 4 build code, and encodeURIComponent charges
//     9 characters for one BMP symbol (☠ -> %E2%98%A0) and 12 for one astral
//     emoji (💀 -> %F0%9F%92%80) against a 512-character design target;
//   - an ASCII-only name has code-unit length === code-point length, so the
//     24 cap, the input's maxlength and this pattern all agree exactly and no
//     truncation can ever split a surrogate pair;
//   - the emoji has a home already. It is the glyph picker, and it is curated
//     for the reason D-00b gives: an emoji nobody's OS knows is a tofu box on
//     a projector.
// / | ~ % # & = < > are excluded on top of that: each is either a delimiter a
// codec or a signature will want, or costs three characters encoded.
var TOKEN_NAME_PATTERN = /^[A-Za-z0-9 ,.'!?()-]{1,24}$/;
var MAX_TOKEN_NAME = 24;
```

```javascript
// [S05] OPS — trim FIRST, then test. "   " passes the pattern and is a name a
// student cannot see, read back, or tell apart from the next one.
function requireTokenName(name) {
  if (typeof name !== 'string') {
    throw new Error('A token type name has to be text.');
  }
  var trimmed = name.trim();
  if (trimmed === '') {
    throw new Error('A token type needs a name.');
  }
  if (trimmed.length > App.data.MAX_TOKEN_NAME) {
    throw new Error('A token type name is at most ' + App.data.MAX_TOKEN_NAME
      + ' characters, and that one is ' + trimmed.length + '.');
  }
  if (!App.data.TOKEN_NAME_PATTERN.test(trimmed)) {
    throw new Error('A name can use letters, numbers, spaces and , . \' ! ? ( ) - '
      + 'only. Emoji go in the emoji row below, not in the name.');
  }
  return trimmed;
}
```

**Where the 24 cap is enforced: BOTH, and the two are different jobs.**
- `maxlength="24"` on the `<input>` is the *ergonomic* half: it stops the student typing a 40-character name and then being told off. It is not a guard — per the HTML spec it applies only to a *dirty* value edited by the user, so a programmatic `.value` write is unaffected. `[CITED: html.spec.whatwg.org/multipage/input.html — "the maxlength attribute — Maximum length of value", where "length" links to infra.spec.whatwg.org/#string-length, defined as the number of code units]`
- The regex in the op is the *guard*, and it runs on the trimmed string before the commit is entered, the same as every other guard in `[S05]`.

**The measured reason not to allow astral characters:** `encodeURIComponent` **throws `URIError`** on a string ending in a lone surrogate. A naive `name.slice(0, 24)` cap over a name of emoji produces exactly that, and Phase 4's encoder would then throw on a build the student can see on screen. Executed (`p7.cjs`): 20 skulls is `.length === 40` / `Array.from().length === 20`; `slice(0,23)` ends in `\ud83d`; `encodeURIComponent` of it → `THROWS: URIError`. **An ASCII allowlist makes this class of bug unreachable rather than handled.** If a later decision reopens Unicode names, the cap must be counted with `Array.from(name).length` and the truncation done on the code-point array, never on the string.

**Concrete cost, measured:** `"Poison stack"` encodes to 14 chars; `"Poison ☠"` to 18; `"Poison 💀"` to 21; 24 astral emoji to **144**.

### Pattern 4 — the picker as list-plus-editor (02.1-02, D-05)

Five changes, each closing a specific measured hazard.

**4a. One button, and the focus hand-back gets simpler.** `onPickerClose` currently builds a selector from `pickerTok` (`'[data-k="tok/' + pickerTok + '"]'`) and guards it against `TOKEN_IDS` first. With one static button the selector becomes a **constant** — no caller-shaped string is built into a selector at all, and the allowlist guard in that function disappears rather than being widened. Give the button `data-k="tok"` and no `data-tok`.

**4b. The signature must fingerprint the whole drawn vocabulary — this is the load-bearing fix.**

The shipped gate is `if (dlg.dataset.sig === sig) { return; }` with `sig = id + '/' + shape + '/' + color + '/' + glyph`. **Measured against the real stub page (`p10.cjs`):** with the Health picker open, committing `tokens.hp.name = 'Vigor'` left `dlg.dataset.sig` at `"hp/sq/green/"` and the heading at `"Health tokens"`; committing a whole new type `t1` left all three grids untouched. A list-plus-editor built on that signature would never show a rename and never show a newly created type.

```javascript
// [S06.2] — the fingerprint covers everything the dialog draws. JSON.stringify
// rather than a joined string, so a name can never collide with a delimiter.
function pickerSig(state, tokenId) {
  var vocab = state.build.tokens;
  return JSON.stringify([tokenId, Object.keys(vocab).map(function (id) {
    var t = vocab[id];
    return [id, t.name, t.shape, t.color, t.glyph, t.scope];
  })]);
}
```

**4c. Stop parsing the open id out of the signature.** `syncPicker` currently does `String(dlg.dataset.sig).split('/')[0]`. Keep the selected id in its own `dlg.dataset.tok` and read it there. This removes a fragile parse *and* removes the only place a name could ever influence a selector. Validate `dlg.dataset.tok` with `requireTokenId`-style logic before use, exactly as `syncPicker` validates against `TOKEN_IDS` today.

**4d. The name `<input>` lives in the static dialog markup and the repaint skips it when focused.**

The dialog repaints on **every frame** while it is open (it rides `SYNC_HOOKS`). A name field rebuilt by `replaceChildren` mid-typing loses the half-typed text: `withPreservedFocus` restores focus and the caret offset, but the freshly built node's `.value` comes from state. Build it once, statically, and apply `setValue`'s rule:

```javascript
var nameField = document.getElementById('tok-pick-name');
if (nameField && nameField !== document.activeElement) {
  nameField.value = live.name;
  nameField.dataset.was = live.value;   // the baseline moves with the text
}
```

This is `[S06.1] setValue`'s D-19 rule, verbatim, for the same reason.

**4e. New `data-k` values, and the removed-row focus case.** List rows get `data-k="pk/list/<id>"`; the name field `pk/name`; the three action buttons `pk/new-unit`, `pk/new-side`, `pk/remove`. `keyed()` is container-scoped, so uniqueness within the dialog is what matters — but keep them globally unique anyway, since `withPreservedFocus`'s comment says first-match. **When the selected type is removed its list row is gone**, so `keyed()` returns null and `fallbackTarget` also returns null (it needs `data-side`, which no picker node has). Focus lands on `<body>`. Handle it explicitly in the remove handler, the same way `peerOrdinal` solved it for the board: after a successful remove, set `pickerTok = 'hp'` and focus the first list row.

**4f. Escape inside the name field will close the dialog.** `<dialog>` fires `cancel` on a close request (Esc, `requestClose()`, the mobile back button); `preventDefault()` on `cancel` keeps it open and suppresses `close`. The event **does not bubble**, so the listener must be on the dialog itself — where `bindPicker` already binds. `[CITED: developer.mozilla.org/en-US/docs/Web/API/HTMLDialogElement/cancel_event]`

```javascript
// [S07.2] bindPicker
dlg.addEventListener('cancel', App.boot.wrap('picker cancel', function (e) {
  var el = document.activeElement;
  if (!el || !el.classList || !el.classList.contains('pk-name')) { return; }
  e.preventDefault();          // Escape in the name field reverts the text,
  revertName(el);              // it does not close the picker out from under it
}));
```

**Not executed — no browser in this repo.** The stub `<dialog>` has `.open`, `showModal()` and `close()` and no close-request behaviour at all, so this path cannot be driven in the Node gate. Mark it for the rehearsal.

### Pattern 5 — labels become sync-driven (02.1-02, ALLOC-10 criterion 1)

A rename must appear "wherever the token type is presented". On the board that is the stat-line label, which `statLine()` builds as `text('span', cls, label)` — a build-time string. Making a rename structural would rebuild both columns on every keystroke of a name edit.

Instead, give the label a key and add one sync pass, mirroring the shipped `.brd-value` pass exactly:

```javascript
// [S06.1] statLine — one attribute more
function statLine(cls, label, valueNode, row, amt) {
  var line = el('div', 'brd-line');
  var lbl = text('span', cls, label);
  if (amt) { setData(lbl, { lbl: amt }); }
  ...
}

// [S06.1] sync() — beside the .brd-value loop
var labels = board.querySelectorAll('[data-lbl]');
for (i = 0; i < labels.length; i++) {
  labels[i].textContent = labelFor(state, labels[i].dataset.lbl);
}

// hasOwnProperty, never a bare index — from Phase 4 this object arrives from a
// pasted build code, and vocab['constructor'] resolves on the prototype.
function labelFor(state, id) {
  var vocab = state.build.tokens;
  if (vocab && Object.prototype.hasOwnProperty.call(vocab, id)
      && typeof vocab[id].name === 'string') { return vocab[id].name; }
  return App.data.DEFAULTS.tokens.hp.name;
}
```

This makes `renameTokenType` a plain `commit` — no structural frame, no column rebuild, no focus churn — and it makes built-in renames (D-10) work through the same one path as custom ones. It is also what makes the picker's list rows show live names.

### Pattern 6 — a zero tally renders as nothing (02.1-02, `<specifics>`)

**Measured behaviour today (`p11.cjs`):** a token row at value 0 keeps its DOM node, keeps `dataset.mode = 't'`, and holds zero children — so it renders as an **empty box beside a live label**, not as nothing. That is exactly the clutter the specifics section rules out: 6 custom types × 24 units = 144 empty labelled boxes.

**Prescription: hide the whole stat *line*, from `sync`, and only for custom types.**

```javascript
// [S06.1] — mark a custom type's line as collapsible when it is built
line.classList.add('brd-line--opt');
setData(line, { amt: tokenId, side: side, unit: unitId });

// [S06.1] sync() — after the .tok-row pass
var opt = board.querySelectorAll('.brd-line--opt');
for (i = 0; i < opt.length; i++) {
  opt[i].hidden = amountFor(state, opt[i].dataset.amt, opt[i].dataset.side, opt[i].dataset.unit) === 0;
}
```

**Never hide a built-in row.** A unit at zero health is meaningful and must stay on screen.

**Three properties that make this safe, each checked:**
1. **Nothing animates when it unhides.** Measured: 0 → 1 appends a token *without* `tok--in` (`syncRow` reads `animate = row.children.length > 0` before the loop), and 1 → 2 appends one *with* it. So a hidden row holds zero children by construction and there is nothing for a `display:none` to cancel — the concern `syncRow`'s own comment raises about `display:none` does not apply at zero.
2. **It needs no structural frame.** The line already exists; a tally 0 → 1 is a plain `commit` and the sync-only frame unhides it. Do **not** make `nudgeTally` structural — that would rebuild both columns on a stepper press and undo Phase 2's whole ALLOC-07 story.
3. **`hidden` alone will not work.** See Pitfall 5.

| "Which of these is live?" marks in the list | A second selection idiom | `pickerSwatch`'s `pk-sw--on` + `aria-pressed` | The list row is the same affordance as a swatch. Reuse the class and the ARIA, or the dialog grows two ways of saying the same thing. |
| A deep clone of a token record | `Object.assign` / spread merge | Field-by-field assignment | `setTokenStyle`'s mutator spells `shape`, `color`, `glyph` out one at a time and says why: "A merge helper here would copy whatever keys the caller supplied, which is precisely how a prototype key slips past an allowlist that only inspected the values." |
| A null-prototype or `Map` vocabulary | Either | A plain object + `hasOwnProperty` on read + a name gate on write | Both measured to fail through `thaw()`. See Alternatives Considered. |

**Key insight:** every hazard this phase can hit has already been hit once in this file and closed with a named mechanism. The failure mode is not building the wrong thing — it is building a second, parallel version of a mechanism that already exists three hundred lines up. Pitfall 12 (single-file entropy) is the live one, and its #1 concrete symptom is duplicated logic drifting apart.

## Common Pitfalls

### Pitfall 1 — the CREATE shape: `tokens[id] = rec` reparents the vocabulary
**Plan:** 02.1-01 · **Severity:** the security criterion
**What goes wrong:** with `id === '__proto__'`, the assignment invokes the `__proto__` setter on `Object.prototype` and **reparents `build.tokens`** instead of adding a key.
**Executed (`p4.cjs`, inside the artifact's own realm):**
```
own keys unchanged                                    ["hp","ap","shield","dmg","dead"]
vocabulary REPARENTED                                 true
tokens.shape now resolves through the injected parent "tri"
Object.prototype itself is clean                      undefined
after ONE more commit (thaw round-trip) it is GONE    true
```
**Why it is nasty:** `Object.keys` is unchanged, `JSON.stringify` is unchanged, `deepFreeze` still reports the slice frozen and a stray write still throws — every gate in the repo reads green. And it **evaporates on the next unrelated commit**, so a student who hits it sees one wrong frame and has nothing left to report.
**How to avoid:** refuse the id before the commit is entered (Pattern 1).
**Warning signs:** any `s.build.tokens[x] = y` where `x` is not a literal.

### Pitfall 2 — the RENAME shape: read-then-write is global prototype pollution
**Plan:** 02.1-01 · **Severity:** the security criterion
**What goes wrong:** `var t = s.build.tokens[id]; t.name = x` with `id === '__proto__'` resolves `t` to `Object.prototype` and writes onto it. **This is the CR-02 shape exactly, and it is `setTokenStyle`'s own mutator body with the allowlist removed.**
**Executed (`p4.cjs`):**
```
BEFORE: ({}).name                                     undefined
threw?                                                null
AFTER: ({}).name  <-- GLOBAL PROTOTYPE POLLUTION      "Poison"
Object.prototype own "name"                           true
JSON.stringify walks past it                          "{}"
```
**Why it is worse than Pitfall 1:** it is *persistent* (nothing in the funnel removes it), it is *global* (every object in the page inherits it), and it is *invisible* to `JSON.stringify` and `deepFreeze` alike. `constructor` behaves differently again — it threw `TypeError: Cannot assign to read only property 'name' of function Object()` — which is a *different* failure with a *different* message, so a single test case does not cover the class.
**How to avoid:** the same gate, and **`renameTokenType` must be gated too, not just `createTokenType`.** Both write paths, and `setTally`/`nudgeTally`, and Phase 4's decoder.
**Warning signs:** a guard applied to create but not to rename.

### Pitfall 3 — an own `"__proto__"` key from `JSON.parse` behaves differently again
**Plan:** 02.1-01 (assertion), Phase 4 (the real exposure) · **Severity:** medium
**What goes wrong:** `JSON.parse` does **not** invoke the setter. It defines an own data property. Executed: `Object.keys → ["hp","__proto__"]`, prototype clean, round-trip stable, `deepFreeze` fine, survives every subsequent thaw.
**The trap is the asymmetry.** After such a value arrives, **reading** `tokens['__proto__']` returns the own record, but **writing** `tokens['__proto__'] = x` reparents instead of updating it — both measured in the same run. A key that reads one way and writes another is the kind of bug that costs an afternoon.
**How to avoid:** the name gate refuses it in both directions. Also: `Object.keys` on an object with any integer-like key **reorders** — measured, `hp, ap, "12", t1, "3"` came back as `["3","12","hp","ap","t1"]`. The `^t[0-9]{1,2}$` pattern's leading `t` is what keeps `Object.keys` in insertion order, which a positional Phase 4 codec will depend on.

### Pitfall 4 — the picker's repaint gate is blind to a name and to membership
**Plan:** 02.1-02 · **Severity:** high — silently ships a dead surface
**What goes wrong:** `sig = id + '/' + shape + '/' + color + '/' + glyph`. A rename changes none of the four; a new type changes none of the four. `picker()` early-returns and the dialog never repaints.
**Executed (`p10.cjs`, against the shipped stub page):** after `tokens.hp.name = 'Vigor'`, `dlg.dataset.sig` was still `"hp/sq/green/"` and the heading still `"Health tokens"`. After creating `t1`, the grids were untouched.
**How to avoid:** Pattern 4b. **Warning sign:** a signature built by concatenating a subset of the fields drawn.

### Pitfall 5 — `hidden` does nothing to an element an author rule gives `display`
**Plan:** 02.1-02 · **Severity:** medium, and it fails *open* (clutter, not a crash)
**What goes wrong:** `.brd-line{display:flex}` and `.unit-line{display:flex}` are author rules; the UA's `[hidden]{display:none}` is a user-agent rule. Author beats UA regardless of specificity, so `line.hidden = true` collapses nothing.
**How to avoid:** add the explicit rule, exactly as the file already does twice — `.err-panel[hidden]{display:none}` (`:387`) and `.st-report[hidden]{display:none}` (`:400`). Follow the precedent:
```css
.brd-line--opt[hidden], .unit-line--opt[hidden] { display:none }
```
**Not executed** — no layout engine here. It is a cascade-origin rule `[CITED: CSS Cascade, author origin outranks user-agent origin]` plus the file's own two-instance precedent. Confirm on the rehearsal.
**Warning sign:** `node.hidden = true` on any node whose class sets `display`.

### Pitfall 6 — the naming trap, and it is worse in this phase than in Phase 2
**Plan:** both · **Severity:** turns the acceptance grep red every time
**Executed (`p9.sh`) — baseline is 0 / 0 on the shipped file. These phrases trip it:**

| Trips ✗ | Safe ✓ |
|---|---|
| `generating an id` (gene-**rating**) | `generated id`, `produced id`, `the id comes from a sequence` |
| `iterating`, `operating`, `separating`, `enumerating`, `decorating`, `moderating`, `accelerating`, `integrating` | `walking`, `working on`, `splitting`, `listing`, `styling` |
| `encounter`, `countermeasure`, `a counter the student increments` | `tally`, `tallies`, `running total`, `count`, `token count`, `sequence` |
| `unbalanced`, `difficulty` | `the tool never rates a build` |

`tally`, `tallies`, `scope`, `name`, `sequence`, `fingerprint`, `annotation`, `createTokenType`, `renameTokenType`, `removeTokenType`, `nextTokenTypeId`, `setTally`, `nudgeTally`, `MAX_CUSTOM_TYPES`, `TOKEN_ID_PATTERN`, `RESERVED_KEYS` — **all verified safe against both greps.**
**The phase's single most likely trip is writing "the id is generating from a sequence" in a comment.** Re-run both greps after every comment block, not at the end of the task.

### Pitfall 7 — a UI act routed through `[S05] dispatch`
**Plan:** 02.1-02 · **Severity:** medium
**What goes wrong:** `selectTokenType` is page work. Adding a `case` to `dispatch` breaks `[S05]`'s banner in both directions, and there is a must-not-regress grep (`case 'openTokenPicker'` = 0) that exists because of it. An act that reaches `dispatch`'s `default: throw` arm shows the student the styled error panel on a first click.
**How to avoid:** push `'selectTokenType'` into `UI_ACTS` and assign `UI_HANDLERS.selectTokenType` from `[S07.2]`. `createTokenType` / `removeTokenType` / `renameTokenType` / `setTally` / `nudgeTally` are the opposite — real state work, real `dispatch` arms.

### Pitfall 8 — D-07's blast radius is the Node gate's selector, not the count of four
**Plan:** 02.1-02 · **Severity:** high — the suite goes red and it is not obvious why
**What actually breaks:**
- `tests/selftest-node.cjs:413` builds four stub buttons from `['hp','ap','shield','dmg']`.
- `:657` and `:857` select `[data-act="openTokenPicker"][data-tok="hp"]`. If `data-tok` goes away, both are `null`.
- Checks **10, 13, 17, 18, 19, 21, 23, 24** hang off those two nodes. Several are written `openBtn !== null && …`, so they fail loudly — but check 24 does `press(openBtn)` unguarded and would throw.
- The **bidirectional stub-drift gate** (`:500–520`) fails the run for every new `id="…"` added to the dialog that is not also built in `makeStubDom`.
- `[S09.5]` in the artifact uses `querySelector('[data-act="openTokenPicker"]')` — first match, no `data-tok` — so **that one survives** the collapse untouched.
**How to avoid:** update the stub and the selectors in the same commit as the markup, exactly as D-07 says. Do not "fix it" by keeping a hidden `data-tok`.

### Pitfall 9 — the stub DOM's selector grammar is smaller than CSS
**Plan:** both (test authoring) · **Severity:** low, but it wastes an hour
`matches()` in the harness supports **only** a tag name, `.class`, and `[data-*]` with or without a value (`SEL_PART`, `:211`). It explicitly rejects any attribute not starting with `data-`. So `[hidden]`, `#id`, `>`, `:has()` and `[aria-pressed="true"]` all silently match nothing. Assert on the `.hidden` **property**, on `className`, or on `data-*`. Note also that `queryAll` walks a root's descendants and **does not test the root itself**.

### Pitfall 10 — a phantom undo step from a guard placed inside the commit
**Plan:** 02.1-01 · **Severity:** medium
Every `[S05]` op puts `requireSide` / `requireDelta` **outside** `App.state.commit`, and `setTokenStyle` puts all four of its guards there too, with a comment saying why. A guard inside the mutator still leaves the entry on the stack in some orderings and, worse, makes a refusal look like a change. **Exception, deliberately:** `addUnit`'s `MAX_UNITS` check *is* inside its mutator, because it needs `units.length` from the detached copy — and that is safe precisely because a mutator that throws leaves no trace (`commit`'s own comment). `createTokenType`'s cap check is the same case and may sit inside for the same reason. Say which you chose and why.

### Pitfall 11 — `setTokenStyle`'s `TOKEN_IDS.indexOf` still refuses every custom type
**Plan:** 02.1-01 · **Severity:** high, and easy to miss
Criterion 2 says a custom type is styled from the same allowlists as a built-in. `setTokenStyle` currently opens with `if (App.data.TOKEN_IDS.indexOf(tokenId) === -1) throw`. Leaving it means a student can create a type and then not restyle it. Replace that line with `requireTokenId(tokenId)` plus a "does it actually exist in the live vocabulary" check — and note that `[S09.6]`'s row `'an unknown token type is refused'` (which passes `'sparkle'`) still passes under the new gate, because `sparkle` fails the pattern. **`'__proto__'` and `'constructor'` rows also still pass**, via the named refusal list. That whole suite survives; only the message text changes.

### Pitfall 12 — `fire()` does not carry a token id
**Plan:** 02.1-02 · **Severity:** low, but it forces the one `[S07.1]` edit
`fire(btn)` sends `{ side, unitId, delta }`. A tally stepper needs a fourth key. `[S07.1]` is meant to be edited by nobody, so this is a conscious, minimal exception: add `tokenId: d.amt` to the payload in `fire()`, `nudgeField()` and `applyField()` — one key, ignored by every existing act. Also add a `FIELD_OPS` entry `tally: { set:'tally', nudge:'nudgeTally', amt:null }` and let the two `.amt` lookups read `FIELD_OPS[d.act].amt || d.amt`, so a tally field reads its quantity from its own `data-amt`. Record it as a deliberate `[S07.1]` change in the plan frontmatter, since the section's banner promises later plans do not touch it.

### Pitfall 13 — `addUnit` must not inherit tallies
**Plan:** 02.1-01 · **Severity:** low, and it will only be noticed by a student
`addUnit` seeds a new unit from `last` (`maxHp`, `shield`). If a `tally` key is ever added to that copy, adding a unit silently duplicates the student's poison markers. It is a rule about *not writing a line*, which is the easiest to lose in a later edit — so assert it: add a unit to a side with tallies and check the new unit has no `tally` key.

## Code Examples

### The create op, end to end (02.1-01)

```javascript
  // A student-made token type (ALLOC-11, D-00e). It counts nothing on its own:
  // the tool stores the number and never infers what it means. Every guard
  // runs BEFORE the commit is entered, matching setTokenStyle above, so a
  // refusal leaves no phantom undo step over a board that never changed.
  //
  // The id comes from a sequence and is never derived from the name (D-13):
  // deriving an id from student text is how a reserved name reaches the key
  // position in the first place. requireNewTokenId is the gate criterion 5
  // names, and it refuses by name rather than dropping silently.
  //
  // Structural, because buildColumn decides whether this type's stat line
  // exists at all, and sync() can neither create a line nor remove one.
  function createTokenType(spec) {
    var p = spec || {};
    var name = requireTokenName(p.name);
    if (App.data.SHAPES.indexOf(p.shape) === -1) {
      throw new Error('Unknown token shape "' + String(p.shape) + '"');
    }
    if (App.data.COLORS.indexOf(p.color) === -1) {
      throw new Error('Unknown token colour "' + String(p.color) + '"');
    }
    if (App.data.GLYPHS.indexOf(p.glyph) === -1) {
      throw new Error('That glyph is not one of the offered set');
    }
    if (App.data.TOKEN_SCOPES.indexOf(p.scope) === -1) {
      throw new Error('A token type is kept either on each unit or on the whole side.');
    }

    var made = requireNewTokenId(nextTokenTypeId(App.state.get().build.tokens));

    commitStructural('token new ' + made, function (s) {
      var made2 = Object.keys(s.build.tokens).filter(function (id) {
        return App.data.TOKEN_IDS.indexOf(id) === -1;
      });
      if (made2.length >= App.data.MAX_CUSTOM_TYPES) {
        throw new Error('This board already has '
          + App.data.MAX_CUSTOM_TYPES + ' token types of your own. '
          + 'Remove one before adding another.');
      }
      // Field by field, never a merge helper: a merge copies whatever keys the
      // caller supplied, which is how a reserved key slips past an allowlist
      // that only inspected the values.
      s.build.tokens[made] = {
        shape: p.shape, color: p.color, glyph: p.glyph,
        name: name, scope: p.scope
      };
    });
    return made;   // [S07.2] selects it in the list once dispatch returns
  }
```

### The remove op — one commit, therefore one Ctrl+Z (D-16)

```javascript
  function removeTokenType(tokenId) {
    if (App.data.TOKEN_IDS.indexOf(tokenId) !== -1) {
      throw new Error('"' + App.state.get().build.tokens[tokenId].name
        + '" is one of the five token types the board is built on, so it cannot '
        + 'be removed. You can rename it instead.');
    }
    requireTokenId(tokenId);

    commitStructural('token remove ' + tokenId, function (s) {
      if (!Object.prototype.hasOwnProperty.call(s.build.tokens, tokenId)) {
        throw new Error('There is no token type "' + String(tokenId) + '" on this board.');
      }
      delete s.build.tokens[tokenId];
      // The tallies go with it, inside the SAME mutator, so Ctrl+Z brings the
      // type and every number back together (D-16).
      ['cats', 'mechs'].forEach(function (side) {
        var faction = s.build[side];
        dropTally(faction, tokenId);
        faction.units.forEach(function (unit) { dropTally(unit, tokenId); });
      });
    });
  }

  function dropTally(owner, tokenId) {
    if (!Object.prototype.hasOwnProperty.call(owner, 'tally')) { return; }
    delete owner.tally[tokenId];
    if (Object.keys(owner.tally).length === 0) { delete owner.tally; }
  }
```

## Codec Forward-Pressure (SHARE-08 / D-18 — sizing only, Phase 4 owns the codec)

Measured with a compact positional scheme in the style CLAUDE.md already used for its 35-char roster figure: one segment per type as `<shapeIdx><colorIdx><glyphIdx><scope><name>` joined by `.`, and tallies run-length encoded over the roster. Full script: `p8.cjs`.

| Item | Chars |
|---|---|
| 6 types, 6-char names | **65** |
| 6 types, 24-char names (the absolute worst) | **173** |
| 3 types, 10-char names (a realistic build) | **44** |
| All 5 built-ins renamed to 8-char names | **64** |
| 1 unit-type, zero on all 12 units, RLE'd | **6** (should encode as **0** — see below) |
| 1 unit-type, non-zero on 2 of 9 cats | **15** |
| 3 unit-types, each on 2–3 units | **41** |
| 6 unit-types, each on 3 units | **119** |
| 6 side-scope types | **35** |
| **6 unit-types × 24 units, every tally non-zero** | **299** |

**Totals against the 512-char design target** (roster 35 + `v1~` prefix and a 4-char checksum ≈ 8):

| Scenario | Total | Verdict |
|---|---|---|
| Realistic: 3 types, 10-char names, sparse tallies | **128** | comfortably inside the 512 target |
| Cap at 6, all names at the 24 max, sparse over 12 units | **335** | inside |
| Pathological: 6 × 24-char names, dense over 24 units | **515** | 3 chars over |

**Conclusion for the planner: the cap of 6 is defensible and should ship at 6.** D-18's "~180 chars before any tallies" estimate is accurate — measured 173.

**But the dominant term is not the type count.** It is the **dense per-unit tally at 299 chars**, which is 1.7× the entire type-definition block. Two consequences worth handing to Phase 4:
1. **D-04's sparse rule has to reach the codec, not just the state.** A type with no tally anywhere must encode as *nothing*, not as a run-length-encoded row of zeros (measured: `24x0` still costs 6 chars per type, 36 for six).
2. **The escalation lever already exists and is not the cap.** CLAUDE.md specifies `CompressionStream('deflate-raw')` + base64url above 800 chars (measured there at 1,165 → 167 chars, zero library bytes). The pathological case is 515 — a third of the way to that trigger — and it requires a board no workshop produces. Lowering the cap below 6 buys ~29 chars per type removed and costs the student an invention.

## Open Questions

1. **Does D-06 (the topbar collapse) have the user's blessing?**
   - *What we know:* D-05 is a sound decision and the reasoning is UX-02-driven; Phase 2 is closed rather than frozen, so forward work is legitimate.
   - *What is unclear:* the user approved four buttons in a real browser and said "approved" without itemising. Replacing them is visible.
   - *Recommendation:* the planner surfaces D-06 as a `checkpoint:human-verify` **before** 02.1-02's first task, not after it. It is one question with a yes/no answer, and getting it wrong costs a rework of the topbar, the dialog and eight harness checks.

2. **Should the name allowlist admit BMP symbols like ☠?** (A5)
   - *What we know:* measured cost is 9 encoded chars per symbol; the ASCII case is 1. The glyph picker already offers 💀 as a curated, cross-platform-checked alternative, and D-00b's whole argument is that OS-supplied emoji do not match across a classroom.
   - *What is unclear:* whether a student typing "Poison ☠" and being refused reads as a sensible boundary or as the tool being fussy.
   - *Recommendation:* ship ASCII with the message that names the emoji picker. Note it as a one-line dial (`TOKEN_NAME_PATTERN`) so a rehearsal can change it in seconds.

3. **Do per-unit tallies get a full `stepper`, or just ± buttons?**
   - *What we know:* `stepper()` gives delta typing, arrow keys and press-and-hold for free, and it is what the board already looks like. It costs one `[S07.1]` payload key (Pitfall 12) and one `FIELD_OPS` entry.
   - *What is unclear:* whether six custom stat lines per unit card, each with a full stepper, is too much furniture on a projector at 24 units.
   - *Recommendation:* full `stepper`, because consistency is worth more than compactness here and Pattern 6 hides every zero line anyway — a board with three types in use shows three extra lines on the units that actually carry them.

4. **Does `dead` get a picker list row?**
   - *What we know:* it is in the vocabulary and in `TOKEN_NAMES`, but has no renderer consumer and no topbar button today ("no renderer consumer yet, so it gets no button").
   - *Recommendation:* include it in the list. D-05 says the picker shows **every** type, `TOKEN_NAMES` already has copy for it, and Phase 5 will draw it. Excluding it re-creates the special case D-05 exists to delete.

## Security Domain

ROADMAP criterion 5 is explicitly a security criterion, so this section is not boilerplate.

### Applicable ASVS categories

| ASVS category | Applies | Standard control here |
|---|---|---|
| V2 Authentication | no | No accounts, no backend, no identity. |
| V3 Session Management | no | No sessions. |
| V4 Access Control | no | Single-user local artifact. |
| **V5 Input Validation & Encoding** | **yes** | Allowlist-on-the-key **and** allowlist-on-the-value, at the `[S05]` boundary, before any commit. `TOKEN_ID_PATTERN` + `RESERVED_KEYS` + `TOKEN_NAME_PATTERN` + the shipped `SHAPES`/`COLORS`/`GLYPHS`/`TOKEN_SCOPES`. Output encoding is structural: every string reaches the page through `textContent`, and the document-wide forbidden-pattern scan is what keeps it that way. |
| V6 Cryptography | no | None used, none needed. (Phase 4's checksum is FNV-1a for truncation detection, not integrity.) |
| V7 Error Handling & Logging | yes (indirect) | `App.boot.wrap` is the single error boundary; a refusal message is student-facing copy, so it must name what was refused without leaking a stack trace. `String(x)` inside message construction so a symbol or object cannot throw while the error is being built — `setTokenStyle` already does this. |
| V12 Files & Resources | yes (by exclusion) | No `fetch`, no `<iframe>`, no `src`, no `url()`. Enforced mechanically by the scan. |

### Known threat patterns for this stack

| Pattern | STRIDE | Standard mitigation | Status here |
|---|---|---|---|
| **Prototype pollution via a caller-supplied key — write path** | Tampering / EoP | Reject the key by name before it indexes an object | **The whole point of this phase.** Two distinct shapes, both executed: Pitfall 1 (reparent) and Pitfall 2 (global pollution). |
| **Prototype pollution via a caller-supplied key — read path** | Tampering | `Object.prototype.hasOwnProperty.call(o, k)` | Already correct in `styleFor`; every new read must match. Measured: `vocab['constructor']` and `vocab['toString']` both return functions from an ordinary object. |
| **Prototype pollution via `JSON.parse`** | Tampering | Reject the key by name after parse | Pitfall 3. Not exploitable this phase (no decoder yet) but the gate must be in place *before* Phase 4 builds one, which is why the ROADMAP made Phase 4 depend on 2.1. |
| DOM XSS via a student string | Tampering | No markup sink exists | Structurally impossible: `textContent` only, enforced document-wide. A name is never interpolated into `className`, a selector, or `data-k` (the id is the identity — D-09). |
| CSS injection via a class suffix | Tampering | Enum id → fixed class suffix | `safeShape` / `safeColor` already map an unknown id to the shipped health entry rather than pasting it through. A custom type inherits this unchanged. |
| Denial of service via unbounded state | DoS | `MAX_CUSTOM_TYPES = 6`, `MAX_ALLOC = 99`, `MAX_UNITS = 24`, `MAX_TOKEN_NAME = 24` | All four are named constants asserted against by `[S09]`. A cap with no assertion is a comment. |
| Silent data corruption via a non-JSON value in state | Tampering | `thaw()` is `JSON.parse(JSON.stringify())` | Measured: a `Map` becomes `{}` with no error. `[S03]`'s banner claims this fails "loudly"; it does not. A `t.throws`-style assertion that a non-JSON value never reaches `build.tokens` is worth one row. |

### Assertions the new `[S09.7]` suite must carry

These are the rows that would have caught what the probes found. All are DOM-free, so the terminal harness gets the whole suite.

1. `createTokenType` with `id` forced to `'__proto__'` is refused **by name**, and `({}).shape === undefined` afterwards.
2. `renameTokenType('__proto__', 'x')` is refused, and `Object.prototype.hasOwnProperty.call(Object.prototype, 'name') === false` afterwards. *(This is the row Pitfall 2 exists for; it is a different code path from 1.)*
3. Same for `'constructor'` and `'prototype'` — three ids × two ops.
4. `Object.getPrototypeOf(App.state.get().build.tokens) === Object.prototype` after every refusal.
5. A refused call leaves `undoDepth` exactly where it was.
6. `removeTokenType('hp')` is refused and names Health.
7. Creating a 7th custom type is refused and names the cap.
8. Create → tally → remove → `undo()` restores **the type and its tallies together**, in one step.
9. `Object.keys(App.state.get().build)` is still `['schema','cats','mechs','tokens']`.
10. `allIntegers` over the whole build slice with 6 custom types and sparse tallies.
11. A tally set to 0 leaves **no key**, and emptying the last one leaves **no `tally` bag**.
12. `addUnit` on a side with tallies produces a unit with no `tally` key.
13. Names: `''`, `'   '`, 25 chars, `'Poison ☠'`, `'Poison/Sear'`, `'<script>'` all refused; `'Poison'` and `"Cat's mark"` accepted; a leading/trailing space is trimmed rather than refused.
14. `setTokenStyle` still works on a custom type, and still refuses `'sparkle'`, `'__proto__'` and `'constructor'`.
15. The suite hands the board back untouched (`App.state.restore(savedAll)`), matching `[S09.3]` and `[S09.6]`.

**Gate checks for `tests/selftest-node.cjs`** (the ones that need the stub page): the single topbar button opens the picker; the list carries one row per vocabulary entry; pressing a row changes the editor; a rename repaints the list **and** the board label (this is the Pitfall 4 regression test — it must fail against a signature-gated picker); creating a type adds a board line; a zero tally leaves the line `hidden === true`; incrementing unhides it; removing the selected type leaves `document.activeElement` on a real node, not `body`.
