### `[S05]` — the id gate

**Analog (the single most important one in the phase):** `setTokenStyle`, `:1502–1573`. It already
allowlists the key **before** it indexes state, and it already puts every guard outside the commit.
Copy the ordering, the `String()`-in-the-message habit and the field-by-field mutator.

```javascript

  // phantom undo step over a board that never changed.
  //
  // The tokenId test is the load-bearing one: s.build.tokens[tokenId] has
  // exactly the shape that CR-02 and WR-02 already had to close twice in this
  // file. Without the allowlist, setTokenStyle('__proto__', ...) reparents the
  // whole vocabulary instead of styling anything. String() inside the message
  // is there so a symbol or an object cannot throw while the error is being
  // built.
  function setTokenStyle(tokenId, patch) {
    if (App.data.TOKEN_IDS.indexOf(tokenId) === -1) {
      throw new Error('Unknown token type "' + String(tokenId) + '"');

    var p = patch || {};
    if (p.shape !== undefined && App.data.SHAPES.indexOf(p.shape) === -1) {
      throw new Error('Unknown token shape "' + String(p.shape) + '"');
```

**The mutator half** (`:1563–1572`) — the comment here is the reason the new create/rename ops must

### `[S05]` — create and remove a collection member (structural discipline)

**Analog:** `commitStructural:1335–1338`, `addUnit:1361–1381`, `removeUnit:1383–1397`. This is the
shipped create-and-destroy pair; a token type is another collection member.

```javascript
  function commitStructural(label, mutator) {
    App.state.commit(label, mutator);
    App.state.invalidate({ structural: true });
  }
```

```javascript
  // A shape change, so it goes through commitStructural and the new card gets
  // built.
  function addUnit(side) {
    requireSide(side);
    commitStructural('add unit ' + side, function (s) {
      var units = s.build[side].units;
      if (units.length >= MAX_UNITS) { throw new Error('That side is full'); }
      var last = (units.length > 0) ? units[units.length - 1] : null;
      var seed = App.data.DEFAULTS[side].units[0];
      var named = nextUnitId(side, units);
      units.push({
        id: named.id,
        name: (side === 'cats' ? 'Cat ' : 'Mech ') + named.suffix,
        maxHp: last ? last.maxHp : seed.maxHp,
        shield: last ? last.shield : seed.shield
      });
    });
  }
```

Three things to copy exactly:
1. `MAX_UNITS` is checked **inside** the mutator, because it needs `units.length` from the detached
   copy — this is the shipped precedent for `MAX_CUSTOM_TYPES` sitting inside `createTokenType`'s
   mutator while every other guard sits outside. Say which you chose and why, as Pitfall 10 asks.
2. `addUnit` seeds field-by-field from `last`. **Do not add a `tally` line here** (Pitfall 13) — and
   because it is a rule about *not* writing a line, assert it.
3. `removeUnit` calls `findUnit` first so a missing id throws with a real message rather than
   splicing at index −1.

**`commitStructural`'s own comment `:1318–1334` is the trigger definition** — "every op that can
change units.length … commits through this rather than through App.state.commit directly." Creating
or removing a type changes what `buildColumn` would build, so it is the same trigger. A *rename* and
a *tally nudge* are **not** — they must stay plain `commit`, or a stepper press rebuilds both
columns and undoes Phase 2's ALLOC-07 story.

### `[S05]` — the produced id

**Analog:** `nextUnitId:1341–1359`. Same reasoning, same shape (scan the live collection, take the
largest suffix in use, add one). The comment is the one to adapt:

```javascript
  // Id allocation is not an implementation detail. data-k, focus restore and the
  // fight slice all key on `id`, and findUnit returns the FIRST match, so a
  // duplicate is silent in every direction at once. prefix + (length + 1)
  // collides after any removal: take c2 out of c1,c2,c3 and the next add
  // produces a second c3, after which findUnit edits the wrong unit and
  // withPreservedFocus refocuses the wrong node. So: scan every existing id,
  // take the largest suffix in use and add one.
  function nextUnitId(side, units) {
    var prefix = side.charAt(0);
    var pattern = new RegExp('^' + prefix + '(\\d+)$');
    var highest = 0;
    units.forEach(function (unit) {
      var m = pattern.exec(String(unit.id));
      if (m !== null && Number(m[1]) > highest) { highest = Number(m[1]); }
    });
    return { id: prefix + (highest + 1), suffix: highest + 1 };
  }
```

**Naming trap, live here:** the adapted comment must not say "generating". `produced id`,
`generated id` and `the id comes from a sequence` were all mechanically checked clean (see
§ Checked vocabulary).

### `[S06.1]` — the tally read

**Source:** `cats-vs-mechs.html:1511–1513` (comment) and `:1521–1536` (code)

### A cap with no assertion is a comment
