## Critical Issues

### CR-01: A half-typed name commits to whichever type the editor moved to — including renaming a built-in on a Remove press

**File:** `cats-vs-mechs.html:4163-4177` (`commitName`), `cats-vs-mechs.html:4122-4131` (`dropType`), `cats-vs-mechs.html:3975-3979` (`showType`), `cats-vs-mechs.html:4185-4189` (`onPickerFocusOut`)

**Issue:**
`commitName` resolves its target at commit time — `pickedTok(dlg)` — but the text it commits was
typed for whatever type was selected when the student started typing. Every control in the picker
that changes the selection does so on **pointerdown**, which runs *before* the browser's focus
change, so `focusout` on the name field arrives *after* `dlg.dataset.tok` has already moved. The
rename lands on the new type.

Reproduced in the stub DOM with faithful browser event ordering
(`pointerdown` → `focusout` on the old node → `focusin` → `pointerup`):

```
start: hp="Health" ... t1="New type" t2="New type"

CASE A — type "Poison" for t2, then click the t1 row:
  after: t1="Poison"  t2="New type"          <- landed on the wrong type

CASE B — type "Venom" for t2, then click "Remove this type":
  after: hp="Venom"  ... t2 removed          <- Health renamed; no error, no warning

CASE C — type "Frost" for t1, then click "New type on the whole side":
  after: t1="New type"  t2="Frost"           <- landed on a type that did not exist yet
```

**Case B is not dependent on native mousedown ordering at all**, which makes it the highest-
confidence half: `dropType` calls `first.focus()` *explicitly* inside the pointerdown handler
(line 4127-4129), after `showType(dlg, FIRST_TOK)` has already repointed `dataset.tok` at `hp`.
A programmatic `focus()` fires `blur`/`focusout` on the previously focused element synchronously
in every engine. So the pending text is committed against `hp`.

This is silent corruption of the student's build with no panel and no signal, on the exact
"type a name, then press the next button" flow the phase exists for. The Node gate cannot see it
because `makeStubDom`'s `node.focus()` (`tests/selftest-node.cjs:320`) only assigns
`doc.activeElement` and dispatches nothing — checks 36-38 drive `focusout` by hand and always
between selections, never across one.

**Fix:** bind the pending text to the type it was typed for, and flush it before the selection
moves. Record the id alongside the baseline on focus:

```js
function onPickerFocusIn(e) {
  var el = e.target;
  if (!isNameField(el)) { return; }
  el.dataset.was = el.value;
  var dlg = pickerDialog();
  el.dataset.forTok = (dlg === null) ? '' : pickedTok(dlg);   // WHICH type this text is for
}

function commitName(el, loud) {
  if (el.value === el.dataset.was) { return; }
  var target = el.dataset.forTok;
  if (typeof target !== 'string' || target === '') { revertName(el); return; }
  try {
    App.ops.dispatch('renameTokenType', { tokenId: target, name: el.value });
  } catch (refused) {
    revertName(el);
    if (loud) { throw refused; }
    return;
  }
  el.dataset.was = el.value;
}
```

and have `showType` flush any pending name *before* it moves the attribute:

```js
function showType(dlg, id) {
  var nameField = (typeof document === 'undefined') ? null
    : document.getElementById('tok-pick-name');
  if (nameField && isNameField(nameField)) { commitName(nameField, false); }  // against the OLD id
  dlg.dataset.tok = id;
  setReveal(id);
  App.render.picker(App.state.get(), id);
}
```

Add a gate check that drives `focusout` *after* a row press / New / Remove and asserts the name
landed on the type it was typed for, and give `makeStubDom`'s `node.focus()` real
`focusout`/`focusin` dispatch so this class cannot hide again.

**Confidence:** Case B **HIGH** (executed; depends only on synchronous programmatic `focus()`
semantics). Cases A and C **MEDIUM-HIGH** (executed against emulated UI-Events ordering — the
ordering is specified, but was not run in a browser here).

### CR-02: Undoing a create leaves the open picker editing a type that no longer exists; the next press raises the error panel

**File:** `cats-vs-mechs.html:3252-3259` (`syncPicker`), `cats-vs-mechs.html:3159-3160` (`picker`'s existence return)

**Issue:**
`syncPicker` bails out when `dlg.dataset.tok` no longer names a live type:

```js
if (!vocab || !Object.prototype.hasOwnProperty.call(vocab, id)) { return; }
```

Bailing means *not repainting*, so the dialog keeps the whole editor for the vanished type: the
list keeps its ghost row, the heading and the name field keep its name, and Remove stays enabled.
Ctrl+Z is bound on `document` and only steps aside for `INPUT`/`TEXTAREA`/`contentEditable`
(`cats-vs-mechs.html:4579-4587`), so it is reachable from inside the modal with focus on a button —
which is exactly where focus sits after pressing **New**.

Executed:

```
made = t1   vocab = hp,ap,shield,dmg,dead,t1
--- after A.ops.undo() ---
vocab            = hp,ap,shield,dmg,dead        <- state is correct
board opt lines  = 0                            <- the board is correct
dlg.dataset.tok  = t1
list rows STILL  = hp,ap,shield,dmg,dead,t1     <- ghost row
heading          = "New type"
remove disabled  = false
press a shape swatch -> ERROR PANEL:
  There is no token type "t1" on this board. — the last good state is still on screen.
press Remove         -> the same panel again
```

The same stale state is produced by `resetToDefaults()` while the picker is open on a
student-made type (also executed). That path self-heals on close-and-reopen; the undo path does
not, because the dialog stays up.

This is the identical failure mode check 23's own comment describes ("it self-healed on
close-and-reopen, which is to say it was wrong for exactly as long as the student was using the
surface") — the repaint hook was built to close it, and it was closed for renames and restyles but
left open for the one commit that *shrinks* the vocabulary. Checks 23 and 35 both undo a rename;
nothing undoes a create.

**Fix:** a selection that no longer names anything is a reason to repaint onto a live type, not a
reason to stop painting:

```js
function syncPicker(state) {
  var dlg = document.getElementById('tok-picker');
  if (!dlg || dlg.open !== true) { return; }
  var id = String(dlg.dataset.tok || '');
  var vocab = state.build.tokens;
  if (!vocab) { return; }
  // A type can vanish under an open editor: undo of a create, or resetToDefaults.
  // Fall back to the type the surface opens cold on rather than leaving a ghost
  // row up over a board that no longer has it.
  if (!Object.prototype.hasOwnProperty.call(vocab, id)) {
    id = App.interactions.FIRST_TOK;                 // export it, as NEW_TOKEN_NAME already is
    if (!Object.prototype.hasOwnProperty.call(vocab, id)) { return; }
    dlg.dataset.tok = id;
  }
  picker(state, id);
}
```

`FIRST_TOK` currently lives private in [S07.2] (`cats-vs-mechs.html:3915`); export it beside
`NEW_TOKEN_NAME` so there is still one spelling. Note that the reveal also needs clearing on that
fallback — reuse `showType` if the tier boundary allows, or add a `setReveal('')`.

Add a gate check: open the picker, press New, call `A.ops.undo()`, flush, and assert the ghost row
is gone and `dlg.dataset.tok` names a live type.

**Confidence:** **HIGH** — executed end to end through the delegated listeners in the stub DOM;
the error-panel text above is the harness's own output.

### WR-02: Stepping a tally down to zero hides its own stepper, drops focus, and leaves no in-page route back

**File:** `cats-vs-mechs.html:2953-2963` (the hide pass)

**Issue:** The hide pass hides a `.brd-line--opt` whose amount is 0 unless its type is the reveal.
The stepper that writes the number is built *inside* that line — which F-02.1-A already
identified — so the last `−` press removes the control the student is pressing. Executed:

```
reveal = ""  tally = 3   line hidden = false, minus button present
press − ×3 -> tally 0
line hidden at 0 = true   <- the −, the field and the + are now inside display:none
```

Two consequences, neither signalled: keyboard focus on the `−` button is dropped to `<body>` when
its ancestor goes `display:none`, and the only way to get the control back is to reopen the picker
and re-select that type. This is reachable without contrivance (write a tally, later open the
editor on another type so the reveal moves off, then step back down to zero) and it is the same
finding F-02.1-A closed, re-opened from the other end.

**Fix:** treat "the student is standing on this line" as a second reveal term, the same way the
editor selection is one:

```js
var focusedLine = (document.activeElement && typeof document.activeElement.closest === 'function')
  ? document.activeElement.closest('.brd-line--opt') : null;
for (i = 0; i < opt.length; i++) {
  opt[i].hidden =
    amountFor(state, opt[i].dataset.amt, opt[i].dataset.side, opt[i].dataset.unit) === 0
    && opt[i].dataset.amt !== reveal
    && opt[i] !== focusedLine;
}
```

A line then collapses on the next frame after focus leaves it, rather than under the finger.

**Confidence:** HIGH for the hiding (executed). MEDIUM for the focus drop — `display:none`
blurring the active element is specified behaviour but was not executed in a browser here.

### WR-03: The picker root has no repeat-Enter suppression, so a held Enter on "New type" runs to the cap

**File:** `cats-vs-mechs.html:4286-4301` (`bindPicker`), `cats-vs-mechs.html:4197-4211` (`onPickerKeyDown`)

**Issue:** [S07.1]'s guard (`cats-vs-mechs.html:3772-3778`) cancels a repeated Enter/Space keydown
on an actionable button, and its comment spells out exactly why: a held Enter synthesises one
`click{detail:0}` per repeat and `onClick` has no `e.repeat` to test. That guard is bound to
`#app`. The dialog is a **sibling** of `#app`, so no event inside it ever reaches it, and
`onPickerKeyDown` returns on its first line for anything that is not the name field.

Phase 2.1 put six new act-carrying buttons plus every swatch and every list row on that unguarded
root. Holding Enter on "New type on each unit" fires one `createTokenType` per OS auto-repeat
until `MAX_CUSTOM_TYPES` disables it — six separate undo entries the student must rewind one at a
time. Gate check 22 asserts the guard for `#app`'s Undo button and has no counterpart here.

**Fix:** add the same two lines at the top of `onPickerKeyDown`, before the `isNameField` return:

```js
function onPickerKeyDown(e) {
  // The same rule [S07.1] applies at #app, for the same reason: the dialog is a
  // SIBLING of #app, so that listener never sees a key pressed in here.
  if (e.repeat === true && (e.key === 'Enter' || e.key === ' ')) {
    var node = e.target;
    var btn = (node && typeof node.closest === 'function') ? node.closest('[data-act],[data-pk]') : null;
    if (btn && btn.tagName !== 'INPUT' && btn.tagName !== 'TEXTAREA') { e.preventDefault(); return; }
  }
  var el = e.target;
  if (!isNameField(el)) { return; }
  ...
}
```

**Confidence:** HIGH for the missing guard (read directly; the two roots are disjoint by
construction). MEDIUM for the auto-repeat click synthesis — that is [S07.1]'s own measured claim,
re-used here, and was not re-measured in a browser.

### WR-04: The type list's scroll position is thrown away on every repaint

**File:** `cats-vs-mechs.html:3100-3107` (`fillList`), `cats-vs-mechs.html:2390-2411` (`withPreservedFocus`), `cats-vs-mechs.html:402-406` (`.pk-list` CSS)

**Issue:** `.pk-list` is `max-height:236px; overflow-y:auto` and the CSS comment states plainly that
it is expected to scroll (11 rows × 44px min-height + gaps ≈ 550px at the cap). `fillList` calls
`list.replaceChildren()`, which empties the box and clamps its `scrollTop` to 0.
`withPreservedFocus` saves and restores `container.scrollTop` — but `container` here is the
**dialog**, not the list, so the list's own scroll offset is never captured.

Every sig change rebuilds the list, and *selecting a row is a sig change* (the id is the first
element of `pickerSig`). So pressing a row near the bottom of a scrolled list jumps the list back
to the top, and `withPreservedFocus` then restores focus with `focus({ preventScroll: true })` —
which deliberately declines to scroll it back into view. The student presses a row and it
disappears upward.

**Fix:** save and restore the list's own offset around the rebuild:

```js
function fillList(list, state, selectedId) {
  if (!list) { return; }
  var scrolled = list.scrollTop;          // replaceChildren clamps this to 0
  list.replaceChildren();
  Object.keys(state.build.tokens).forEach(function (id) {
    list.appendChild(pickerListRow(state, selectedId, id));
  });
  list.scrollTop = scrolled;              // after the new content exists, per withPreservedFocus
}
```

**Confidence:** MEDIUM — `replaceChildren` clamping `scrollTop` and `preventScroll` declining to
scroll are both specified, and the code path is certain, but the visual consequence depends on
layout and there is no layout engine here.

### WR-05: Every new type arrives indistinguishable from the last one

**File:** `cats-vs-mechs.html:3925` (`NEW_TOKEN_NAME`), `cats-vs-mechs.html:4084-4095` (`liveLook`), `cats-vs-mechs.html:4103-4116` (`makeType`)

**Issue:** A new type inherits `liveLook(pickedTok(dlg))` — the look of the type currently in the
editor — and `makeType` then calls `showType(dlg, made)`, so the *next* New inherits the type just
made. Two consecutive News therefore produce two records with the same name, the same shape, the
same colour and the same glyph. Executed:

```
hp="Health" ... t1="New type" t2="New type"      (both sq/green/'' — identical rows)
```

On the board that is two identically-labelled, identically-drawn lines on every unit card, and in
the picker two identical rows. Nothing but the invisible `data-tok` tells them apart. D-11 permits
duplicate names, but permitting them and *manufacturing* them are different things, and this is
the first press of the phase's headline flow.

**Fix:** either number the placeholder, or rotate the inherited colour — the second reads better
on a projector and costs one line:

```js
function makeType(dlg, scope) {
  var look = liveLook(pickedTok(dlg));
  var used = Object.keys(App.state.get().build.tokens).length;
  var made = App.ops.dispatch('createTokenType', {
    name: NEW_TOKEN_NAME + ' ' + (1 + Object.keys(App.state.get().build.tokens)
      .filter(function (k) { return App.data.TOKEN_IDS.indexOf(k) === -1; }).length),
    shape: look.shape,
    color: App.data.COLORS[used % App.data.COLORS.length],
    glyph: look.glyph,
    scope: scope
  });
  showType(dlg, made);
}
```

Keep [S09.7]'s existing assertion that the produced name is one `requireTokenName` accepts.

**Confidence:** HIGH — executed.

### WR-06: `nextTokenTypeId` re-spells `TOKEN_ID_PATTERN` inline

**File:** `cats-vs-mechs.html:1479-1491`

**Issue:**

```js
var TOKEN_ID_PATTERN = /^t[0-9]{1,2}$/;     // [S01], exported, asserted against
...
var m = /^t([0-9]{1,2})$/.exec(id);         // [S05], a second copy of the same fact
```

The scanner's digit width is written a second time. This file's stated rule is one place per fact,
and the two are load-bearing together: widen `TOKEN_ID_PATTERN` to three digits (a plausible Phase
4 edit if the cap moves) and `nextTokenTypeId` would stop seeing `t100`…`t999`, compute a
`highest` that is already in use, and hand back a colliding id. Layer 3 turns that into a thrown
error rather than a silent overwrite, so it is a correctness *hazard*, not a live bug — but it is
the exact drift the rest of the section is written to prevent.

**Fix:** derive the scanner from the exported pattern, or export a single capturing form:

```js
// One spelling of the id shape. TOKEN_ID_PATTERN is the test; this is the same
// shape with the sequence number captured, built from it rather than beside it.
var TOKEN_ID_CAPTURE = new RegExp(
  App.data.TOKEN_ID_PATTERN.source.replace('[0-9]{1,2}', '([0-9]{1,2})')
);
```

or simplest: move a `TOKEN_ID_CAPTURE` constant into [S01] next to `TOKEN_ID_PATTERN` and have
[S09.7] assert the two agree on `t1`, `t99` and `t100`.

**Confidence:** HIGH — read directly; the collision path is reasoned, not executed.

### IN-03: Escape can never close the picker while the name field has focus, even with nothing to revert

**File:** `cats-vs-mechs.html:4304-4319` (the `cancel` listener), `cats-vs-mechs.html:4209-4210`

**Issue:** The `cancel` listener declines every close request whose `document.activeElement` is the
name field, unconditionally. Once the text has already been reverted (or was never edited), a
second Escape still cannot close the dialog. The student has to Tab out or reach Done. The
listener's comment frames this as "narrow on purpose", but the narrowing is on *where focus is*,
not on *whether there is anything to cancel*.

**Fix:** decline only when the field is genuinely dirty:

```js
dlg.addEventListener('cancel', App.boot.wrap('picker close request', function (e) {
  var el = (typeof document === 'undefined') ? null : document.activeElement;
  if (!isNameField(el)) { return; }
  if (el.value === el.dataset.was) { return; }   // nothing to put back — let it close
  e.preventDefault();
  revertName(el);
}));
```
