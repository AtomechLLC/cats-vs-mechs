# Phase 2.1 Plan 04: The Picker Becomes a List-Plus-Editor Summary

**The picker now draws one row for every token type on the board — a student's invention and one of the five it is built on are the same kind of row — the repaint gate fingerprints the whole drawn vocabulary instead of four fields of one record, the selected id lives in an attribute rather than being parsed back out of a delimiter-joined string, and the phase's live defect is gone: opening a type of your own no longer hands you the Health editor.**

`TOKEN_NAMES` is deleted. There is exactly one place in the file that turns a token type into a display label, and it is `labelFor`.

## The live defect, closed

Plans 02.1-01 and 02.1-02 both flagged and deliberately left it. `[S06.2] picker()` opened with a **membership** test against the five shipped ids and, on a miss, quietly swapped in the first of them. It was harmless until plan 02.1-02 shipped `createTokenType`; after that, any surface handing the picker a student-made id would have shown the **Health** editor, said nothing about it, and then restyled Health on every press.

It is replaced by the **existence** test the rest of the file already uses:

```javascript
var vocab = state.build.tokens;
if (!vocab || !Object.prototype.hasOwnProperty.call(vocab, tokenId)) { return; }
var id = tokenId;
```

`grep -c "TOKEN_IDS.indexOf(tokenId) === -1" cats-vs-mechs.html` returns **0**.

A made-up type resolves to itself. An id that names **nothing** paints no dialog at all rather than painting the wrong one — the same refusal `if (!dlg) { return; }` above it already makes. Nothing shipped can reach that branch today: the topbar offers only the five, and all five refuse removal.

| Node | Tag / class | Attributes |

| `#tok-pick-list` | `div.pk-list` | `role="group"`, `aria-labelledby="tok-pick-list-label"`, empty |

| `#tok-pick-remove` | `button.brd-btn` | `data-act="removeTokenType"` `data-k="pk/remove"` |
| `#tok-pick-name-label` | `h3.pk-legend` | "Name" |
| `#tok-pick-name` | `input.pk-name` | `type="text"` `autocomplete="off"` `maxlength="24"` `aria-labelledby="tok-pick-name-label"` `data-k="pk/name"` |

The name field is **not** a stepper field, and the markup says why: `isField` keys on the stepper input's own class and everything downstream of it is numeric by construction, so "Poison" would be parsed as a figure and refused on Enter. `maxlength` is ergonomic only — it stops a student typing past the cap and then being told off — and it counts UTF-16 code units while `MAX_TOKEN_NAME` counts **code points**, so the two legitimately disagree for an emoji name. The guard is `requireTokenName`; the safe cut is `clampTokenName`.

`[C07]` gained four rules. `.pk-list` **scrolls** rather than shrinking its type — the reason the dialog is this size is that a room reads it off a projector, so a longer list costs height and never legibility. `.pk-list-item` is `.pk-sw` laid along the line, with the same `--tok` override, the same `color-mix()` chrome derived from the token's own colour, and the same `.pk-sw--on` + `.pk-check` selected state. `.pk-name` borrows `.err-detail`'s chrome, the file's only other free-text input. `.pk-actions--new` pushes to the start of the line, because it acts on the list above it, where `.pk-actions` pushes Done to the end. No disabled styling was written: `.brd-btn` already carries `&:disabled`, and a second rule for it would be a second place for the two to disagree.

**In the same commit**, `tests/selftest-node.cjs` grew `KNOWN_IDS` by seven and built a matching node for each in `makeStubDom`, with the three button datasets copied from the markup so plan 02.1-05's handlers route to real names. The drift gate is fatal in **both** directions and reports **35 shell ids**.

### Task 2 — the fingerprint, the list, and the deleted table (`f31303f` RED, `e180636` GREEN)

**`pickerSig(state, tokenId)`** returns `JSON.stringify([tokenId, Object.keys(vocab).map(id => [id, name, shape, color, glyph, scope])])`. The idiom is unchanged — a repaint that changes nothing must still touch no nodes — and only the input widens. `JSON.stringify` of an **array**, never a joined string: a name is text a student types, so every delimiter is a character they can enter, and a joined fingerprint could be made to report "nothing changed" for a change (T-02.1-20).

**`dlg.dataset.tok`** is written beside `dlg.dataset.sig` and read by `syncPicker`. The `split('/')[0]` parse is gone — `grep -c "dataset.sig).split('/')"` returns **0** — and with it the only place a typed name could have reached a selector (T-02.1-19). Nothing reads a value back out of `dataset.sig` any more; it answers one question, "has anything drawn here moved", and `dataset.tok` answers the other.

**`syncPicker` validates against the live vocabulary**, not against `TOKEN_IDS`. Keeping the allowlist test would have stopped the per-frame repaint the moment a student opened a type of their own — which is gate check 23's own bug, re-introduced one layer down.

**`fillList` / `pickerListRow`** build one row per entry in `Object.keys(build.tokens)`, `dead` included. `Object.keys` is own-enumerable by definition and the two reads inside the row builder are `labelFor` and `styleFor`, both `hasOwnProperty`-guarded, so no bare vocabulary lookup happens on the path (T-02.1-21). Each row is a real `<button>` carrying `data-act="selectTokenType"`, `data-tok="<id>"` and `data-k="pk/list/<id>"` — the **id**, never the name.

**The name field is painted, never rebuilt**, and skipped while it holds focus. That is `setValue`'s rule applied to text instead of a figure, and it is the whole reason the field is static markup: the dialog rides `SYNC_HOOKS`, so it repaints on every frame while it is open. `dataset.was` moves with the displayed text for the reason `showFieldValue` gives — left stale it would restore a name state no longer holds.

**Remove and the two New buttons are re-decided from state on every repaint.** Remove is closed for one of the five (D-15); both New buttons close at `MAX_CUSTOM_TYPES` (D-18). Being derived per frame rather than toggled by whoever last pressed something is what makes an undo move them too.

**`TOKEN_NAMES` is deleted.** `grep -c "TOKEN_NAMES"` returns **0**. Its own comment — "the dialog's heading is the only place a student is told which type they are editing" — is the sentence that stopped being true this phase, and the region now carries a `DELIBERATELY ABSENT` block saying so.

**No second `SYNC_HOOKS` entry.** `grep -c "SYNC_HOOKS.push"` is **1**, unchanged. The list-plus-editor inherits the per-frame repaint from the hook that is already there.

## Known Stubs

**The three new buttons and every list row are display-only.** `data-act="selectTokenType"`,
`createTokenType` and `removeTokenType` all reach `onPickerPress`, which matches neither, so a press
is a no-op. This is deliberate and is the plan's explicit boundary: plan **02.1-05** registers
`UI_HANDLERS.selectTokenType`, adds the create/remove/rename press paths, and collapses the topbar's
four buttons into one — and those changes must land **together**, because the collapse is what makes
`btn.dataset.tok` stop naming one of the five. Splitting them would open the picker on `undefined`.

The enabled state of the three buttons is **not** a stub: it is computed from state on every repaint
and asserted at both ends (Remove closed for a shipped type, open for a student's own; both New
buttons open below `MAX_CUSTOM_TYPES` and closed at it).

`#tok-pick-name` is painted and reverts correctly, but nothing yet **reads** it back — the commit

## Notes for the next plans

1. **`dlg.dataset.tok` is the contract.** Read the selected type there and nowhere else. Do not
   re-introduce a parse of `dataset.sig`; nothing reads a value out of it by design.
2. **`onPickerClose` in `[S07.2]` still tests `App.data.TOKEN_IDS.indexOf(pickerTok)` and builds
   `[data-k="tok/' + pickerTok + '"]`.** It is correct today because the topbar offers only the five.
   The topbar collapse (D-05) makes `pickerTok` mean something else, so both lines are 02.1-05's to
   change **in the same commit as the collapse**.
3. **`#tok-pick-name` must not be given `.stp-field`.** `parseField` is numeric and `FIELD_OPS` is a
   frozen four-row allowlist; a name typed into a stepper field is refused on Enter. It needs its own
   commit path — `clampTokenName` at the keystroke boundary, `requireTokenName` as the backstop,
   `dataset.was` as what Escape puts back.
4. **A repaint while the name field has focus deliberately skips it.** Any handler that writes the
   field must therefore also move `dataset.was`, or the next blur will re-read its own text as a
   fresh edit.
5. **Changing a type's `scope` after creation would be structural** — the line moves between two
   regions — and D-03 says it cannot be changed at all. The dialog offers no control for it.
6. **The stub-DOM probe is the instrument for `[S09.7]`'s DOM block** and lifts `makeStubDom()` out
   of the harness at run time rather than copying it. If a future plan is allowed to move the gate
   count, those rows are ready to become real terminal coverage the moment `MouseEvent` is stubbed.
