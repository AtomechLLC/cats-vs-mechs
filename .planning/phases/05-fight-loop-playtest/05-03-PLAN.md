<objective>
Two halves of the round loop that are pure state work, built before the op that spends them.

**The split** is FIGHT-16 and it is the one resolution rule the developer specified directly: damage
spends shield before it reaches health, and the tool **shows** that split rather than applying it
silently. Showing it means the arithmetic has to return three separate numbers rather than one, so
that `[S06.8]` can write *"Shield absorbed 2 of the 3. Health took 1."* rather than *"3 damage"* —
which teach different things. `[S02]`'s banner is the boundary: it returns numbers, and the page owns
every word.

**The declaration** is FIGHT-12: the student says what both sides do this round, with the performer
and the unit it points at, and **nothing resolves while declaring.** Phase 3.1 put the *proposal* on
the DOM specifically so *"there is no state in which a proposal exists and has not been accepted"* —
and that argument does not transfer, because a declaration is a state in which an intent exists and
has not resolved **by design**. That is what "before anything resolves" means. It must survive a
repaint, survive `structure()`, be undoable, and be readable by Advance. So it lives in
`state.fight.decl`, and this plan says so in the file rather than leaving the next reader to weigh a
paragraph four thousand lines away that argues the other way for a different reason.

Purpose: the arithmetic and the intent, both provable in CI, both before anything can spend them.
Output: one pure function in `[S02]`, three ops in `[S05]`, and the rows that hold them.
</objective>

<the_line_this_phase_walks>
This is the plan where the line between bookkeeping and combat automation is easiest to cross by
accident, so it is drawn here in one sentence and then applied item by item:

> **Advance may restate; it may never decide.** Every number written must be one the student put on
> the board themselves.

This plan writes the arithmetic and records the intent. It does **not**:

- choose which action a side uses — the student declares it;
- choose a target — 03.1-07 already ruled this, and its words are the rule: *"who an action may be
  pointed at is exactly the sort of question this tool does not answer"*;
- decide whether a relationship applies (Fly beats Slash) — `REFERENCE.beats` is reference material
  and must gain no consumer in `[S05]`;
- decide whether an effect fires — `keywords` has no writer and gets none;
- decide whether a unit is dead — `alive` is a stored flag, never inferred;
- **refuse a declaration a side cannot afford** — D-23, and `affordability` carries the never-disable
  rule in its own comment. The tool records what was declared and reports the shortfall. A student
  who wants to declare something and argue about it is the workshop working correctly.

The split writes `shield` and `hp` and **nothing else**. It does not write `alive`. That is D-00d and
it is the obvious next line, which is exactly why it needs an assertion rather than a comment.
</the_line_this_phase_walks>
