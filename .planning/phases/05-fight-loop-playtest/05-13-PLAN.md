**The arithmetic behind D-27's preview, the record shape that makes one row hold one action, and the
default that keeps targeting to one click.**

D-27: *"As actions are selected, deplete the resources. Re clicking an action should undo that
preview. picking another action should undo any changes and apply the new one."*
D-27's addendum: *"Default target to the lowest health enemy. Add a button to change target (rather
than require a picker every time)."*

Three separate things, and this plan builds all three in the tiers that own arithmetic and records —
before a single node is drawn, so the surfaces in 05-14 and 05-15 read rather than invent.

**The depletion is a READING.** Plan 05-07 measured, and 05-10's acceptance run read back verbatim,
that `apSpent` is `0` at every observable moment: `advanceRound` spends each declared cost and
refills both pools from the build **in the same commit**, so no frame is ever rendered between the
two writes. Two admissible fixes were written into the file and handed to the developer. D-27
chooses the second — *"a reading for what this round's declarations have spoken for"* — and promotes
it from a bar figure to the core interaction. **`advanceRound` is not touched.** FIGHT-09's *"spent
visibly distinct from available"* is served by the same mechanism, and the apSpent-reads-zero blocker
is closed here.

**The radio is a record shape.** *"[C1] [ACTION] [ACTION] [ACTION] ← buttons to pick one."* One unit,
one action. `declareAction` appends today, so the same unit could hold three. Amending the op is the
only place that can be true from — a surface enforcing it would put the rule one layer up where no
gate is watching, which is the exact failure `[S06.7]`'s banner names about D-23.

**The default is a derivation and NOT an op behaviour.** The op must keep storing `null` when it is
handed `null`, because *"Hairball, no target"* has to stay recordable and `namedOr` was written for
exactly that. So the default lives in `[S02]` as a pure read, the SURFACE calls it and passes the
answer as `at`, and the record that comes out is indistinguishable from one a student picked by hand
— which is the property that makes the change-target button a change rather than an override.
