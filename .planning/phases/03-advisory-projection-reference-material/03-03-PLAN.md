<the_fact_that_shapes_this_plan>
**`#strip` is a CHILD of `#board`, not a sibling of it.** The shell is:

    <div class="board" id="board">
      <section class="brd-col" id="col-cats"></section>
      <aside class="brd-strip" id="strip">…</aside>
      <section class="brd-col" id="col-mechs"></section>
      <p class="muted" id="board-empty">…</p>
    </div>

`sync()` scopes every pass to `board.querySelectorAll(...)`, so a node appended to `#strip` is
**already inside the per-frame reconcile**. `structure()` replaces only the interiors of `#col-cats`
and `#col-mechs`, so strip content **survives a rebuild**. Both were executed against the artifact.

Four rules follow, each proved by probe, each a silent failure if broken:

1. **Never `.brd-value` + `data-amt` for a projection figure.** `amountFor` knows only
   `ap | dmg | ehp | hp | shield | <studentTypeId>` and its fall-through is `return 0;` — an unknown
   `data-amt` renders a silent `0` with no error. Use `data-prj="turns" | "work"` and `.prj-*`.
2. **Never `data-k` in the strip, and never a `data-act` + `data-side` pair on one strip node.**
   `keyed()` takes the **first** document match and `#strip` precedes `#col-mechs`, so a strip
   `data-k="mechs/ap"` steals focus restore from the real field. Executed and reproduced.
3. **Never `.brd-line--opt` in the strip.** That class means "hide when the tally is zero" and the
   hide pass reads `amountFor`, which returns 0 for any projection key — the line would be `hidden`
   forever.
4. **Build once, sync every frame.** `structure()` never touches the strip, so a `dataset.built`
   flag is sufficient and correct. `dlg.dataset.tok` in `[S06.2]` is the direct precedent.

**`SYNC_HOOKS` is not on `App.render`'s frozen surface.** Measured: `structure, sync, picker,
amountFor, labelFor, COMPACT_AT, MAX_UNITS`, and the object is `Object.freeze`d. There is no way to
push a hook from outside `[S06]`. The projection therefore **must** be a sub-region inside the
`[S06]` IIFE — it cannot be a top-level section. `[S06.2]` is the exact template.
</the_fact_that_shapes_this_plan>

<no_verdict_by_shape>
D-13 is held structurally, not by good intentions. Build to these and assert them.

1. **One panel per side, built by ONE function called twice with the side as an argument.** A builder
   that names both sides in one body is the shape a shared axis, a paired bar or a midpoint marker
   takes. This is the only structural place the prohibition can be held.
2. **No figure without a side.** Every `.num` node inside `#strip` must have a `[data-side]`
   ancestor. A figure with no side is, by construction, a figure about both sides.
3. **No inline style anywhere in the strip.** The entire artifact makes exactly **one** `.style`
   access today (`documentElement.style.setProperty('--topbar-now', …)`, line 4724). A proportional
   bar, a shared scale or a midpoint marker cannot be drawn without an inline width or a per-frame
   custom property, and both are `.style`. So the count stays at 1 and `#strip [style]` stays empty.
4. **No shared scale in CSS.** No `.prj-*` rule may contain a `width:` with a `%`, `calc()` or
   `var()` term, and no CSS custom property may be declared on a `.prj-*` selector. A shared axis
   needs a shared length.
5. **Colour encodes faction and token identity only.** No `--green` / `--gold` / `--coral` anywhere
   in `.prj-*` — those are token-identity colours and would read as quality. Use `--ink`,
   `--ink-dim`, `--line`, `--panel`.

Checks 1 and 2 are exact. Checks 4 and 5 are heuristics that catch drift, not a determined author —
say so in the comment, in the register of the harness's own honesty clause.
</no_verdict_by_shape>
