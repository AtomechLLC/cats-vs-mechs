<the_three_relationships>
From `PROJECT.md` § Source material, transcribing the whiteboard: *"Expected counters: Slash < Fly,
Hairball < Lasers, Fly < Recharge."* Read as ordered pairs where the second wins the exchange:

    Fly       beats  Slash
    Lasers    beat   Hairball
    Recharge  beats  Fly

**Two things to render as given rather than silently fix.**

1. **`Recharge` beats `Fly` is intra-Mechs.** Both are Mechs actions. That is a faithful
   transcription of the board, and it is also why the map belongs in a full-width band rather than
   in either faction column. Flag it; do not correct it.
2. **Verb agreement.** "Lasers **beat**", "Fly **beats**". Put the connective **in the data**, one
   per pair, so no rendering code has to guess at English grammar. Action names render verbatim from
   `DEFAULTS[side].actions[].name`.

`Fly` appears on both sides of the chain — it beats Slash and loses to Recharge. That short
rock-paper-scissors loop is exactly why three sentences beat a 3×3 grid on a projector, which is
what D-12 and the specifics note already decided.
</the_three_relationships>

<the_naming_trap_at_its_sharpest>
**REF-01 is the counter map, and `counter` is a banned substring — case-insensitively, over the whole
file, in code, in comments and on screen.** The feature cannot be named after itself. `encounter` is
out for the same reason.

Render the band's heading as **"What beats what"**. Name the data key `beats`. `beats`, `over` and
`under` all measure 0 whole-file hits.

Do not use `winner` or `loser` as field names: 03-01 put both on Layer A, so using them as keys makes
the gate unsatisfiable. `rating` hides inside `generating`, `operating`, `iterating`, `separating`,
`enumerating` and `decorating` — write "generated" and "operated".
</the_naming_trap_at_its_sharpest>
