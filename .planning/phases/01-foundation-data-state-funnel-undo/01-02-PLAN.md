**Constants.** `UNDO_LIMIT = 30` and `COALESCE_MS = 500`, both named and exported on the public
surface so the self-test asserts against the constants rather than against magic numbers.

**The state object.** One private `cur`, initialised to
`{ build: App.data.defaults(), fight: null, ui: { kbdNav: false } }` and immediately deep-frozen.
Three slices with three different lifetimes (ARCHITECTURE.md's slice table): `build` round-trips
through the share code and is snapshotted for undo; `fight` is snapshotted for undo and never shared;
`ui` is in neither. There is **no `mode` key** anywhere — mode is derived from `fight !== null`, so the
two can never desynchronise after an undo. State holds integers, booleans, short strings and arrays of
those, and nothing else: no DOM nodes, no functions, no `Map`, no `Set`, no `Date`, no class instances.
That one constraint is what independently buys snapshot undo, URL serialization and console debugging.

The `fight` slice, when non-null, has the shape
`{ round: 1, turn: 'cats', log: [], cats: { ap, units: [ { id, hp, alive } ] }, mechs: { … } }`.
`fight` stores only what changes during a fight; names, actions, damage and keywords are read through
`build`, so a unit has exactly one identity. `alive` is its own boolean and is never derived from
`hp === 0` (D-00d). Define the shape now even though turn advance, action-point spending, damage
application and the log are Phase 5 — the shape is the Phase 1 decision, the operations are not.

**`thaw(state)`** — private. Returns `JSON.parse(JSON.stringify(state))`: an unfrozen deep copy, and
simultaneously the enforcement mechanism for the JSON-clonable rule, since anything non-clonable
vanishes loudly rather than surviving.

**`freeze(state)`** — private. Calls `App.data.deepFreeze(state)` and returns it. Do not write a
second recursive freeze; plan 01-01 already exported one.

**`commit(label, mutator)`** — the single mutation funnel (D-00a). In order:
  1. Serialise the pre-mutation `{ build, fight }` with `JSON.stringify`. `ui` is deliberately excluded
     from the snapshot (D-09) — undoing a collapsed panel is confusing, not an edit.
  2. Coalesce: if the newest undo entry has the same `label` and its timestamp is within `COALESCE_MS`,
     refresh that entry's timestamp and push nothing; otherwise push `{ label, snap, t }` and, when the
     stack exceeds `UNDO_LIMIT`, `shift()` the oldest off. Coalescing is what makes press-and-hold one
     undo step instead of forty (D-10). The window slides on each repeat.
  3. `thaw` the current state into a working copy, run `mutator(working)`, then re-`freeze` it and
     assign it to `cur`. The freeze-thaw-refreeze cycle is what makes "nothing mutates outside
     `commit()`" a mechanical guarantee rather than a code-review promise: between commits the live
     object is deep-frozen, so a stray write throws `TypeError` in strict mode.
  4. Increment a private `commits` counter.
  5. Call `App.serialize.scheduleUrlSync()` — a declared no-op today; the call site exists so Phase 4
     never has to be retrofitted into the funnel.
  6. Call `invalidate()`.

  There is no redo stack and no `future` array. Redo is not a v1 requirement (UX-01 specifies undo
  only) and dead machinery in a single file is exactly the entropy PITFALLS Pitfall 12 warns about.

**`commitUi(label, mutator)`** — the same thaw/mutate/refreeze cycle for `ui`-only changes, but it
pushes nothing onto the undo stack and does not call `scheduleUrlSync`. It exists as a separate,
greppable function so that "which mutations are undoable" is answerable by reading two function names
rather than by auditing an options flag at forty call sites.

**`undo()`** — pops the newest entry; returns `false` when the stack is empty (a no-op, never an
error, because Ctrl+Z at the bottom of the stack is normal). Otherwise parses the snapshot, thaws the
current state, replaces `build` and `fight` from the snapshot while preserving the live `ui` slice,
re-freezes, calls `scheduleUrlSync()` and `invalidate()`, and returns `true`. Because snapshots span
both `build` and `fight`, undo crosses the setup/fight boundary — undoing past a start-fight
un-starts it (D-08). Never clear the undo stack, including on reset: a mis-clicked reset must be
recoverable (D-12, PITFALLS Pitfall 8).

**`invalidate(opts)`** — the rAF coalescer (ARCHITECTURE.md Pattern 5, measured to collapse 50 calls
into 1 render). Private `dirty`, `structural` and `frames` flags. When `opts.structural` is truthy set
the structural flag. If already dirty, return. Otherwise mark dirty and schedule one frame. The frame
callback returns immediately when `dirty` is already false (which makes it idempotent and means a late
timer firing after a manual `flush()` cannot double-count), otherwise clears `dirty`, increments
`frames`, and calls `App.render.structure(cur)` when the structural flag was set — clearing it — then
always calls `App.render.sync(cur)`. Both are declared no-ops until Phase 2; this plan builds the
scheduling machinery, not the render.

  Schedule the frame with a private helper that calls `requestAnimationFrame(fn)` **as a bare global
  call** when `typeof requestAnimationFrame === 'function'`, and falls back to `setTimeout(fn, 16)`
  otherwise. Do not store `requestAnimationFrame` in a variable and call it through that variable —
  detaching it from its global receiver throws `Illegal invocation` in Chrome. The fallback is what
  lets `tests/selftest-node.cjs` run the file with no DOM.

**`flush()`** — runs any pending frame synchronously and returns whether one was pending. Needed so
the self-test can assert coalescing without becoming asynchronous, and useful to Phase 2.

**Public surface**, frozen: `get()` (returns the frozen `cur`), `commit`, `commitUi`, `undo`,
`undoDepth()` (the length of the undo stack), `invalidate`, `flush`, `stats()` (returns
`{ commits, frames, undoDepth }`), `UNDO_LIMIT`, `COALESCE_MS`.

## Trust Boundaries

Offline, zero-dependency, single-file artifact: no backend, no auth, no accounts, no PII, no network
calls. The register below is deliberately narrow and lists only threats that are real for this plan.

| Boundary | Description |
|----------|-------------|
| pasted link → `location.hash` | `#selftest`, `#throwinit` and `#throwhandler` are read from a hash a classmate can control by pasting a link into the course Discord thread. |
| thrown error text → error panel DOM | The panel echoes `err.message` and `err.stack`, which can embed attacker-influenced substrings (an id from a pasted link, and from Phase 4 decoded build-code content). |
| handler input → `ops` setters | Every value written into state passes through the `ops` layer. |
