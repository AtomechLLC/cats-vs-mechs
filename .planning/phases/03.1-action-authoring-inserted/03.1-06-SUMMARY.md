### PROBE U — the freeze row, and the probe that was wrong TWICE

Research recorded this probe as wrong once. **The first attempt here was wrong too, in a new way**, and the finding is worth more than the probe: the helper was declared at CommonJS module top level (sloppy) and called from inside a `'use strict'` IIFE, so the directive did nothing.

> **Strictness is a property of where the WRITE is written, not of where it is called from.**

Rewritten with the write lexically inside each mode:

```
--- 1. STRICT, frozen term, the row everyone writes ---
   "a write to a frozen term throws" reads: true
--- 2. THE SAME ROW, ON NOTHING AT ALL ---
   reads on null:      true
   reads on undefined: true
--- 3. THE NEGATIVE CONTROL, which is what tells them apart ---
   unfrozen copy accepts the write: true
   null accepts the write:          false
--- 4. SLOPPY mode, the same frozen term, the same row ---
   "a write to a frozen term throws" reads: false
   term after the write: d=-3
```

**Section 2 is the finding the plan asked for: the row without a control is GREEN over a term that does not exist.** Section 4 is research's original point re-proved — the write neither threw nor landed, so a row asserting the throw goes red for a reason unrelated to the freeze, and a row asserting "the value did not change" goes green whether the record was frozen or the write was simply discarded. The freeze row in `[S09.10]` was tightened to assert its subject is a three-field record before it asserts the refusal (`2747a45`).
