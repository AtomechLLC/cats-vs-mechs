## The tripwire, as rewritten

What stood in `[S09.9]`:

```js
t.eq('the actions the cards read and the actions the projection reads are '
  + 'the same actions',
  JSON.stringify([App.state.get().build.cats.actions, ...]),
  JSON.stringify([App.data.DEFAULTS.cats.actions, ...]));
```

It is **removed**, with a paragraph in its place recording that it was tripped on purpose and where the replacement went. The two reads are now one read, so that row would from here on be comparing a value with itself.

The replacement is a **DOM walk in the rendered half**, in two halves that catch different defects:

1. `createAction('cats', 'Pounce')` — a STRUCTURAL commit, so it runs the builder — then read the cats column's card names back: `["Slash","Hairball","Screech","Pounce"]`, with the mechs column still at 3.
2. `renameAction('cats', made, 'Prowl')` — a PLAIN commit, so it runs the sync passes and never the builder — then read back with **no structural frame in between**: `["Slash","Hairball","Screech","Prowl"]`.

Plus a third path: `renameAction('mechs','lasers','Pew')` moves the band to `["Fly beats Slash","Pew beat Hairball"]` while the keyword cards stay `Evade,Range,Shield`.

**And it is mirrored into CI as checks 64 and 64b**, because probe L-1 measured that the artifact's own row is DOM-only and the terminal run stayed spotless over a broken build. See below.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] A comment's apostrophes formed a pseudo-literal holding a gate word**

- **Found during:** Task 1.
- **Issue:** `…the artifact's own judgements skips it; and [S06.1]'s per-frame pass…` — Layer B extracts single-quoted spans, and the text between the two apostrophes is one of them: `PROJ-06 VIOLATION … [judgement]: 's own judgements skips it; and [S06.1]'`. The run aborts before any suite executes. This is the naming trap in a shape neither CONTEXT nor RESEARCH lists: not a banned stem inside an ordinary word, but a banned word sitting between two possessive apostrophes.
- **Fix:** reworded to `…the gate that walks the page for the words the ARTIFACT may not use skips it.`
- **Committed in:** `ef6f6a3`

**2. [Rule 2 — Missing critical functionality] ACT-07's line said something untrue-in-spirit on the shipped board**

- **Found during:** Task 3, on the first measurement.
- **Issue:** the plan's own acceptance criterion says *"the line is empty on the shipped board"*, and it was not: Slash and Lasers both carry a `{ tok: 'hp' }` transformation, so the picker opened cold on `Health is named by Slash, Lasers. Removing it will leave those actions without a term.` — a consequence stated for a removal the surface does not offer, because Remove is disabled for all five shipped types. That is precisely the noise `[S06.3]`'s admission line refuses on the same grounds one region over.
- **Fix:** `namedByText` returns the empty string for a type the board is built on, asking `isShippedType` — the same question the enable pass beside it asks, and the point rather than a coincidence: the line is about a removal, so it speaks exactly when there is a removal to speak about. It still disables nothing, and check 40f holds the Remove button's state identical through every state the line passes through.
- **Committed in:** `80dd6bb`

**3. [Rule 1 — Bug] `pickerSig` widened to the RECORD would have repainted a dialog nothing had changed on**

- **Found during:** Task 3, immediately after deviation 2.
- **Issue:** the plan says to widen the signature to `actionsNaming`'s record. With the shipped-type arm above, that record moves for changes the line does not show — an action naming one of the five, or naming a type the picker is not open on — and the region's own stated idiom is that *a repaint that changes nothing must still touch no nodes*.
- **Fix:** the third element is `namedByText(state, tokenId)`, the STRING the line draws. "The signature moves exactly when the line moves" becomes true by construction rather than by two lists being kept in step. It is one element of the array, never appended to a joined string, for the reason the fingerprint was an array in the first place.
- **Committed in:** `80dd6bb`

### Corrections to the plan's own text, recorded rather than silently absorbed

- **"the line is empty on the shipped board" was not true as written**, and could not be made true by the shipped data — see deviation 2. The plan's later criterion, *"With a student-made type named by one authored action, the line names both"*, is what the implementation satisfies, and the shipped board is quiet because a shipped type cannot be removed.
- **"driving a `createAction` that names the type"** describes an op this phase does not have. `createAction` writes `cost: [{ tok: 'ap', n: 1 }]` and empty `req` / `xf`, so it can only ever name `ap`. ACT-05 is half-delivered by design (D-05b) and the editor is plan 03.1-05's. The rows drive the real `createAction` **and then** write the term through `App.state.restore`, which is `[S09]`'s documented writer and exists for exactly this. Check 40c asserts both halves, which makes it a stronger row than the one specified: an action that exists but names nothing leaves the line alone.
- **Probe M's stated expectation is not met by the existing check, and the plan predicted that.** Recorded above with the row that closes it.
- **Probe L-1 revealed that the plan's Task 1 acceptance criteria were satisfiable with a broken artifact.** The criteria are written about the DOM run; CI is the Node run. Checks 64 and 64b close that, and no future plan should assume a `[S09.*]` row behind `typeof document === 'undefined'` protects anything in CI.
- **A third Layer B gap, measured and reported, not exploited.** Plan 03.1-03 reported `\blead\b` missing `leads` and `/dominat/` missing `dominant`. Probe L-3 adds: **Layer B's `/\bwin\b/i` DOES catch the fragment `'Win'`**, so the naive split-a-banned-word evasion is already covered for that word — but `'bet' + 'ter'` is not, and no rule in either list matches a fragment of `better`. Layer C caught it, which is the layering working as designed. Neither list was widened here; a widening belongs with the plan that measures its false positives.
