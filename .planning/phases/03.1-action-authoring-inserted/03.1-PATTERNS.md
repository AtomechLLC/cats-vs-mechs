### Work unit 1 — `[S01]` DATA: the record and the id constants

**Analog A — the id-shape constants.** Copy this trio structure-for-structure, renaming `TOKEN`→
`ACTION` and `t`→ the chosen prefix. The **width is written once** and both readings are built from
it; that is the load-bearing part.

`cats-vs-mechs.html:929-943`
```js
  var TOKEN_ID_DIGITS = '[0-9]{1,2}';
  var TOKEN_ID_PATTERN = new RegExp('^t' + TOKEN_ID_DIGITS + '$');

  // The same shape with the sequence number captured. Built beside the pattern
  // from the same source rather than derived from it by rewriting its text: a
  // rewrite that stopped matching would fail silently, into a scanner that
  // reads undefined for every id and never says so.
  var TOKEN_ID_CAPTURE = new RegExp('^t(' + TOKEN_ID_DIGITS + ')$');

  // The named refusal list. It is the MESSAGE, not the defence: the pattern
  // above is what actually keeps these out of the key position, and this array
  // is what lets the refusal name what was refused instead of dropping it
  // silently or calling it merely unknown (D-14). Frozen for the same reason
  // the allowlists are.
  var RESERVED_KEYS = deepFreeze(['__proto__', 'constructor', 'prototype']);
```
`RESERVED_KEYS` is **reused, not duplicated** — it is already exported and already the message layer
for both id spaces.

**Analog B — the cap constant.** `:945-949`

D-10's cap gets the same treatment: one named constant, exported, with the encoding arithmetic in
the comment. RESEARCH § OQ-3 supplies the arithmetic (~38 chars worst case per authored action) and

**Analog C — allowlists are frozen arrays, and index order is a contract.** `:893-895` and the

**Analog D — the record literal itself.** `:1067-1088` (`DEFAULTS`). Note the two things that make

### Work unit 2 — `[S02]` MODEL: the D-14 generalisation

**Analog:** the four functions being generalised, all of them.

`cats-vs-mechs.html:1232-1241`
```js
  function bestDamage(faction) {
    return faction.actions.reduce(function (n, a) { return a.dmg > n ? a.dmg : n; }, 0);
  }

  // Throughput is capped by the shared action-point pool, not by unit count.
  // That cap is the whole point of holding action points at faction level.
  function factionDps(faction, activeUnits) {
    var active = (activeUnits === undefined) ? faction.units.length : activeUnits;
    return Math.min(faction.ap, active) * bestDamage(faction);
  }
```

**The section's own three prohibitions, from its banner at `:1206-1215` — every new function is
bound by all three:**
```
 * PURE derivations. Every function takes the state, or a slice of it, as an
 * argument. Nothing here reads the state singleton, reads or writes the page,
 * or stores a derived value — a derived value kept in state becomes a second,
 * mechanical reason for the projection to disagree with the board.
 * ... nothing below produces a symbol or a string,
 * because the page owns how a range is written down.
```

**The comment idiom to copy for `actionApCost`'s `null` return** — a refusal taken above the
arithmetic rather than repaired below it, `:1265-1279`:
```js
  // A hit of zero is reachable, not hypothetical: a faction whose actions are
  // all status effects has a best damage of 0, and ceil(9 / 0) * 0 is NaN,
  // which reaches a projector as three letters. The refusal therefore sits
  // ABOVE the reduce rather than inside it, so no unit is ever divided by
  // zero at all. Written as "not greater than zero" so a NaN hit is refused
  // by the same line.
  function soakTotal(faction, hit) {
    if (!(hit > 0)) { return 0; }
```
`bestPair` must not reintroduce a division. RESEARCH § D-14 explains why the derivation stays
`min(floor(ap / cost), active)` and never a fractional rate: `soakTotal` divides by `hit` and
`workLines` prints both operands on a projector, where `[S06.3]` D-06 forbids a non-whole number.

**Two named consumers to check before changing arity:** `turnsToWipe` at `:1315-1326`, and
`amountFor(state, 'dmg', side)` in `[S06.1]` which draws each faction head's Damage row from
`bestDamage` (RESEARCH Pitfall 9). Both keep working under the recommended generalisation —
measured 1 / 3 on the shipped board — but a plan that moved the semantics further would move the
red diamonds with nothing in `[S06.1]` saying why.

**Export block to extend:** `:1328-1338`.

### Work unit 4 — `[S05]` OPS: the three-layer action-id gate (D-13)

**Analog:** `requireTokenId`, and its ordering comment is the part to copy verbatim in spirit.

`cats-vs-mechs.html:1719-1740`
```js

  // the two and a student who reaches __proto__ reads "that is not a token
  // type on this board", which explains nothing about what actually happened.
  function requireTokenId(tokenId) {
    if (typeof tokenId !== 'string') {
      throw new TypeError('A token type is named by a short id, and this one is a '
        + (typeof tokenId) + '.');
    }
    if (App.data.RESERVED_KEYS.indexOf(tokenId) !== -1) {
      throw new Error('"' + String(tokenId) + '" is a name JavaScript keeps for '
        + 'itself, so a token type cannot use it — it would corrupt the board '
        + 'rather than name anything on it.');
    }
    if (App.data.TOKEN_IDS.indexOf(tokenId) !== -1) { return tokenId; }
    if (!App.data.TOKEN_ID_PATTERN.test(tokenId)) {
      throw new Error('"' + String(tokenId) + '" is not a token type on this board.');
    }
    return tokenId;
  }
```

**The sequence, and its ceiling refusal.** `:1813-1827`
