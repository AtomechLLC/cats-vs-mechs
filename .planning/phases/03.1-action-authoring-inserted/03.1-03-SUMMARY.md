### PROBE J — the name guard moved inside the commit

**J-1, run first and RECORDED AS VACUOUS.** The plan's stated expectation is that moving `createAction`'s name guard inside the commit reddens the **undo-depth** row. Moved to the top of the mutator:

```
641 passed, 0 failed
```

Green, and it cannot be otherwise. `commit()` runs its mutator **before** it records anything, so a guard placed anywhere inside a commit still leaves no phantom undo step — that is the very property the file cites to justify the one documented in-commit exception (the cap check). Per this project's rule, the code was investigated rather than the probe re-run, and the finding is that **undo depth cannot detect guard placement anywhere in this file.**

What guard placement *does* change is the refusal **order**. At the cap there are two true refusals available, and which one a student reads depends on whether the name gate sits ahead of the cap check or behind it. A row was written for exactly that, and then the probe was re-run with the guard in its natural in-commit home — beside the fields it feeds.

## The two decisions this plan settled, in writing

Both were forks the pattern map flagged and declined to settle. Each is recorded beside the code **and** as a suite row carrying its reason in the label.

1. **A shipped action can be renamed and re-costed, but not removed.** D-07 says a shipped action and a student's action are the same kind of thing, and that is honoured everywhere else — one list, one editor, no second tier. Removal is the exception for the same reason the five shipped token types cannot be removed: the reference band's relationship records name the six shipped actions by id, and a removed one would leave the band naming nothing. Six rows assert the rename succeeds; six assert the removal is refused **by the LIVE record's name**; and one renames `Lasers` to `Beam` and confirms the refusal follows the student's choice.
2. **`renameAction` is a PLAIN commit; `createAction` and `removeAction` are structural.** A rename changes a label, which plan 03.1-04 makes a per-frame read on the card. A create or a remove changes how many cards a column holds. The consequence is written into the code for whoever writes the next suite: a structural-frame behaviour cannot be asserted through a rename, because a rename runs the sync pass and never the structural one.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] The authoring banner named the two dynamic-code entry points literally, and the harness scans for them by name**

- **Found during:** Task 2.
- **Issue:** The banner's whole point is to say that an authored rule is a data record and never a program, and the natural sentence spells out the two constructs this project bans. `tests/selftest-node.cjs`'s forbidden-pattern scan reads the source, not the semantics: `FORBIDDEN PATTERNS in cats-vs-mechs.html (1): line 2973 [Function constructor]: new Function`. The run aborts at `exit=1` before any suite executes.
- **Fix:** the sentence now describes them — "the two dynamic-code entry points this project bans, the ones the harness scans for by name" — which is the file's own describe-never-quote rule applied to a second word list.
- **Committed in:** `53b4618`

**2. [Rule 3 — Blocking] A suite label tripped Layer B of the PROJ-06 gate**

- **Found during:** Task 3.
- **Issue:** "a rewritten rule is a silently changed rule, which is worse for a student than a refused one" is the plan's own phrasing of the no-rewrite rule, and `worse` is on the 23-word literal list. A self-test label is a string literal like any other — the same hazard plan 03.1-02 recorded.
- **Fix:** reworded to state the harm rather than compare two harms: "a rewritten rule is a rule the student never wrote, with no step to undo and nothing on screen to notice."
- **Committed in:** `2fac2c9`

**3. [Rule 1 — Bug] `renameAction` carried an in-mutator existence check that could never be the one that fires**

- **Found during:** Task 3, while planning probe I-3.
- **Issue:** the no-op contract forces a read of the live record before the commit is entered, and `commit()` runs its mutator once and synchronously on a copy of that same state. A second existence test inside the mutator is therefore unreachable — the exact shape plan 03.1-02's probe H found in `actionModelled` and called *"an arm no probe can hold to account"*. Shipping it would have made the gate look thicker than it is.
- **Fix:** removed, with the reasoning and the probe-H precedent written where it stood. `createAction`'s and `removeAction`'s in-mutator checks are kept — `removeAction`'s is load-bearing (probe I-3 proves it), and `createAction`'s is the file's documented "makes *should never* checkable rather than assumed" idiom, transcribed from `createTokenType`.
- **Committed in:** `2fac2c9`

**4. [Rule 1 — Bug] The `actionsNaming` comment claimed a measurement this implementation does not have**

- **Found during:** final verification.
- **Issue:** the comment carried the research's 0.75–2.0 µs figure. Measured on the shipped function: 7.9 µs at six actions and 75.8 µs at fifty-four — roughly 40x the quoted number, because the research sketch carried none of the `hasOwnProperty` and `Array.isArray` guards. A teaching artifact that states a measured number it did not measure is the one failure this project treats as unforgivable.
- **Fix:** the comment now carries this file's own four measurements, the controls, the reason for the discrepancy and the caveat that they were read under Node. The conclusion is unchanged.
- **Committed in:** `f1ff508`
