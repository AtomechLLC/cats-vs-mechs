- **The gate can see this phase's work.** `</main>` closes at `cats-vs-mechs.html:692` and `<dialog id="tok-picker">` opens at `:728` — a sibling of `#app`, so 91 rendered strings were outside the PROJ-06 gate entirely. ## The two gate gaps, reported and not exploited

Recorded as two comment lines beside the word list in `tests/selftest-node.cjs`, per the plan:

- `{ label: 'lead', re: /\blead\b/i }` does **not** match `leads`. `leads on damage` passes.
- `{ label: 'dominate stem', re: /dominat/i }` does **not** match `dominant` — the word is `dominan-t`. `the dominant action` passes.

Neither list was widened in this plan and neither gap is used by any copy it ships.

## Decisions Made

1. **Dialog strings feed the same word list and the same check 48.** The plan said not to build a second word list; the record each harvested string carries (`{ s, where }`) supplies the locality a second check would have given, and check 48's failure message now names the surface a hit came off.
2. **`MAX_ALLOC`'s literal moved to `[S01]`.** See Deviation 2.
3. **The dialog floor is 84, not 90.** The acceptance criterion asked that the measured count be ≥ 90 (it is 91); the floor is a separate number and is set from the measured sensitivity of the harvest, which is one string per list row.
4. **The picker's opener is pressed rather than `showModal()` called.** Driving the real `data-act` handler means a dialog whose opener was never registered harvests an empty box and trips its own floor, instead of passing on a hand-opened dialog nothing routes to.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Three in-file rows counted `[data-lbl]` nodes document-wide and broke when the dialog got one**

- **Found during:** Task 1, by the full DOM run (the Node harness could not see it — it never calls `App.selftest.run()` against a DOM).
- **Issue:** `[S09.7]` asserted `document.querySelectorAll('[data-lbl="hp"]').length === 12` and `[data-lbl="dmg"].length === 2`. The picker keeps its list rows after it closes, so once `[S09.5]` has pressed the token-appearance button, a document-wide count reads twelve unit cards **plus one row per live type plus the editor heading**. Measured 14 against an expected 12; three rows red.
- **Fix:** A local `boardLabels(id)` helper scoped to `#board`, used by all four label rows, with a comment stating that the scope **is** the assertion: these rows are about what `sync()`'s label pass reaches, and that pass queries `board`.
- **Files modified:** `cats-vs-mechs.html`
- **Verification:** DOM run 520/0 restored, then 537/0 after Task 3.
- **Committed in:** `7d0cf40`

**2. [Rule 3 — Blocking] `MIN_XF_DELTA` / `MAX_XF_DELTA` could not be both "derived from `MAX_ALLOC`" and "in `[S01]`" without moving the literal**

- **Found during:** Task 2.
- **Issue:** The plan requires the two bounds to derive from `MAX_ALLOC` "so the number is written once", and its `must_haves` and plan 03.1-06's context block both place them in `[S01]` / `App.data`. `MAX_ALLOC` lived in `[S05]`, which runs **after** `App.data` is built, so `[S01]` could not read it. Re-typing `99` in `[S01]` was the one thing the plan forbade.
- **Fix:** The literal `99` now lives in `[S01]` beside the two derived bounds, with the reason written out; `[S05]` does `var MAX_ALLOC = App.data.MAX_ALLOC;` and **still exports it**, so every existing assertion against `App.ops.MAX_ALLOC` reads the same constant. A new row asserts `App.data.MAX_XF_DELTA === App.ops.MAX_ALLOC`, so the two tiers cannot drift.
- **Files modified:** `cats-vs-mechs.html` (`[S01]`, `[S05]`, `[S09.1]`)
- **Verification:** `App.ops.MAX_ALLOC === 99` and `App.data.MIN_XF_DELTA === -99`; 429/0 Node, 537/0 DOM.
- **Note on section ownership:** the plan's `section_ownership` named `[S01]`; this touches two lines of `[S05]`. No other plan in this phase's wave 1 exists, so no collision was possible.
- **Committed in:** `38681f4`

**3. [Design note, not a fix] Probe C reddens check 47d, not check 48**

- **Issue:** The plan's acceptance text says removing the exemption marker should make **check 48** fail. It cannot, as the checks are built: check 48 reads the harvest of the *shipped* board, where no type is named after a comparative word. The check that drives the rename is 47d, and that is the one that goes red.
- **Why this is the right shape:** putting the rename into check 48's own harvest would have left the gate's main PROJ-06 assertion reading a board no student has, and would have made every later hit message harder to read. 47d uses the same `RENDERED_VERDICT_WORDS` list and the same `verdictHitsIn()` function as 48 — there is no second word list, which is what the plan actually forbade.
- **Recorded rather than fixed.**

**4. [Rule 1 — Bug] Three comments in `tests/selftest-node.cjs` became untrue as a result of this change**

- **Issue:** The Layer A preamble stated "Layer C harvests #app" as a live limitation; limitations entry 5 said a string shown "only inside an open dialog" is out of reach; the limitations preamble said "Four behaviours" over a list of eleven.
- **Fix:** All three corrected in place, with entry 5 pointing at new entries 12 and 13, which name what genuinely remains out of reach (close-request behaviour per dialog, and words a dialog paints only after something happens inside it).
- **Committed in:** `7d0cf40`
