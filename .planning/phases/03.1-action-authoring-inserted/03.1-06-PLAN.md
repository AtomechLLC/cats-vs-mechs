<objective>
Let the student write the rule: what it costs, what it needs, and what it changes.

The record already carries the fields (plan 03.1-01) and the surface already exists (plan 03.1-05).
This plan adds the three write paths and the three editors, and it is where every hazard the research
measured about numbers entering state actually bites: `NaN` launders through the state's own clone
into `null`, and the integer walk accepts `null`. `int()` and `requireDelta()` at the op boundary are
the only defence, so every number entering a cost, a requirement or a transformation must pass one
of them.

Purpose: ACT-02, ACT-03 and ACT-04, end to end.
Output: three ops, three editors, and the rows that would go red without either.

<the_line_this_phase_walks>
Writing a rule is not running one. These ops set fields on a definition. Nothing here spends a cost,
tests a requirement against a unit, or moves a token on the board.

**`eval` and `new Function` are banned, and this is the plan where the temptation is real.** A
condition, a formula field, or a "when" expression would each be a string the tool has to interpret.
Every term this plan writes is a record of an id, an allowlisted word and a whole number. If an
editor field would need to be parsed as anything richer than that, it has left the phase — the
conditional transformation is deferred by name in CONTEXT.md.
</the_line_this_phase_walks>

    Three plain-commit ops, each with every guard outside the commit.

    `setActionCost(side, actionId, tokenId, n)`: sets the action's single cost entry. D-01 says a
    cost is a token type and an amount, so the list holds at most one entry — enforce that as a
    named constant rather than an inline literal. `requireSide`, `requireActionId`, `requireTokenId`

    `setActionReq(side, actionId, index, tokenId, n)`: sets one requirement slot. The index is bounded
    by `MAX_ACTION_REQ` and is refused, not clamped, if it is outside — a clamp would silently write
    the wrong slot. `int` with a floor of zero. Removing a requirement is setting its slot empty;
    give that one named path rather than two spellings.

    `setActionXf(side, actionId, index, who, tokenId, d)`: sets one transformation slot. The index is
    bounded by `MAX_ACTION_XF` and refused if outside. `who` is checked against the exported `XF_WHO`
    allowlist and refused by name if it is not in it — never interpolated anywhere. The amount goes
    through the signed bound `MIN_XF_DELTA` / `MAX_XF_DELTA`, and a zero amount is refused with a
    message saying a change of nothing is not a change. Removing a transformation is setting its slot
    empty, by the same one named path.

    Every record is built FIELD BY FIELD. Never a merge helper, never a spread of a caller's object,
    for the reason `setTokenStyle` and `createTokenType` both give. Every term is an array of records
    carrying the token id as a VALUE; nothing in this plan puts a token id in a key position.

    Do not distinguish an absent field from a present-but-undefined one — measured, they are the same
    thing one commit later. Treat a missing list as an empty list, everywhere.

    Add the three dispatch arms, reading key by key. Extend the export block.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a typed amount -> state | free text becomes a number that later drives a figure on a projector |
| a chosen token id -> a term | an id crosses into a record that other code resolves |
| a chosen `who` -> a term | a word that selects a party |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03.1-23 | Tampering | `NaN` reaching state and laundering into `null` | mitigate | every number passes `int()` or `requireDelta()` at the op boundary; a walk row asserts no `null` survives inside any term |
| T-03.1-24 | Tampering | prototype pollution through a token id in a term | mitigate | `requireTokenId` on every term write; the term shape has no key position, proved by round-tripping a reserved word as a VALUE |
| T-03.1-25 | Tampering | a caller-supplied key riding in on a merge | mitigate | field by field, never a merge or a spread; probe R proves the row can fail |
| T-03.1-26 | Elevation of privilege | a rule becoming a program | mitigate | terms hold only allowlisted words and whole numbers; a source check for `eval` / `new Function` and a term-walk check, both numbered, both proved by probe T |
| T-03.1-27 | Tampering | `who` interpolated into a class or a selector | mitigate | checked against the exported `XF_WHO` allowlist and refused by name; the page maps it to fixed words |
| T-03.1-SC | Tampering | npm/pip/cargo installs | accept | zero packages installed by this phase |
</threat_model>
