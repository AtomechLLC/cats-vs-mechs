<objective>
Attach the surface, and get a build code onto a clipboard without lying to anybody about whether it
worked.

`grep -c "clipboard\|writeText\|execCommand\|navigator\."` over this artifact reads **0**. Nothing
here has ever called a platform API with a permission model, an asynchronous result, or a failure the
page must branch on. This is the one genuinely new technique in the phase, it has no analog anywhere
in the repo, and **it is unreachable from the Node harness entirely** — not merely unrendered, absent
from the runtime. So this plan does two things carefully: it builds the tiers so that the tier a
Node sandbox can actually reach is the one SHARE criterion 1 requires to be a real surface, and it
names the rest as rehearsal items rather than folding them into a claim.

**One ordering rule is inverted here, exactly once, and deliberately.** Every press handler in this
file dispatches first and does page work only after dispatch returns, so an op that refuses throws
into the boundary and the page work never runs. The copy press cannot follow it: CLAUDE.md's
HIGH-confidence finding is that `writeText` must be called synchronously inside the user gesture from
Chrome 107, so the build code must be produced **before** the clipboard call and never after. The
plan records this as a stated divergence with its reason, in the code, because a later reader will
otherwise read it as the ordering rule having been forgotten.

Purpose: SHARE-01, and the surface's operation end to end short of loading and resetting.
Output: `[S07.4]`, a three-tier copy, and the checks that hold them.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a press -> the platform | the first call in this project's history to an API with a permission model and an asynchronous result |
| a press -> an act | a delegated listener turns a control into either page work or a dispatch, and the split is asserted |
| an asynchronous failure -> the error boundary | a clipboard denial is not a defect and must not look like one |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-26 | Repudiation | an optimistic line claiming a copy that did not happen | mitigate | the line branches on the tier that succeeded; probe U proves the one tier CI can reach is asserted |
| T-04-27 | Denial of service | a listener bound outside the boundary leaving the surface dead and silent | mitigate | every listener through `App.boot.wrap`, checked structurally by name and arity and floored on the count; probe T proves it |
| T-04-28 | Denial of service | an unhandled clipboard rejection reaching the window listener and raising the styled panel over a permission denial | mitigate | both arms of the asynchronous result are handled inside the press |
| T-04-29 | Elevation of privilege | a state op parked in `UI_ACTS` so a refusal stops being raised | mitigate | the act partition is collected off the page and asserted both ways; probe V proves it |
| T-04-30 | Information disclosure | the address bar offered as the share unit, leaking a home directory path | mitigate | the surface offers the code only; no control in `[S07.4]` reads or presents the location |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | zero packages installed by this phase |
</threat_model>
