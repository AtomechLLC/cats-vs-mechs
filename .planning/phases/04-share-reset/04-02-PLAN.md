<objective>
Write the grammar, both directions, and prove the round trip on boards nobody hand-wrote.

This is the plan the whole phase rests on, and research already did the hardest part of it: a
complete reference codec was written, round-tripped byte-for-byte against six boards produced by
driving the shipped ops, and measured. **Two grammar bugs were found and fixed inside that reference,
and both decoded to a valid WRONG build rather than to an error** — which is precisely the "loads
garbage silently" failure SHARE-03 exists to prevent, and neither would have been visible to an
encode-only size measurement. Both are named below so they are not rediscovered, and both get a
deliberate-failure probe so the rows that catch them are proved live rather than assumed.

The two schema decisions that make the numbers work are not optimisations and must not be simplified
away: a **name table** (each distinct name encoded once, referenced by a base36 index) and **two
independently run-length-encoded unit streams** (health-and-shield separate from the tally bag).
Without them the same six boards measure 33 / 272 / 271 / 1,781 / 4,729 and the ceiling is 4,839 —
2.4 times the message limit and beyond rescue without the compression this phase has ruled out.

Purpose: SHARE-02, SHARE-03, SHARE-04 and SHARE-08's whole mechanism, and every row that proves it.
Output: `encode`, `decode`, and a round trip asserted over six driven boards.

<!-- The verified grammar, from 04-RESEARCH.md § Grammar. All integers are base36 lowercase.
     Amounts are 0..99, so one or two characters. Reproduced here so the executor needs no
     second document open. -->

code    = "v1" "~" body "~" ck4
body    = names "~" vocab "~" sideA "~" sideB
names   = "N" [ b64 *( "." b64 ) ]                     ; base64url of UTF-8, one per DISTINCT name
vocab   = "V" [ vrec *( "_" vrec ) ]
vrec    = builtinIx "." shapeIx "." colorIx "." glyphIx "." nameIx
        | "C" seq "." shapeIx "." colorIx "." glyphIx "." scopeIx "." nameIx
sideA   = "A" count "~" ap "~" stats "~" tallies "~" gaps "~" sideBag "~" actions
sideB   = "B" ... (identical)
stats   = rle( maxHp "!" shield )
tallies = rle( bag )                                   ; bag = "" | tokIx "!" n *( "." tokIx "!" n )
gaps    = [ index "!" suffix *( "-" index "!" suffix ) ]
sideBag = bag
actions = [ arec *( "_" arec ) ]
arec    = head "." [nameIx] "." costs "." reqs "." xfs
head    = shippedIx | "C" seq
costs   = [ tokIx "!" n ]
reqs    = [ tokIx "!" n *( "-" tokIx "!" n ) ]
xfs     = [ whoIx "!" tokIx "!" (d + MAX_XF_DELTA) *( "-" ... ) ]   ; BIASED — no sign character
rle(x)  = elem *( "-" elem ) ; elem = [ count "*" ] payload
ck4     = FNV-1a(body) -> base36, last 4 characters

<the_two_grammar_bugs>
Both were found during research, both are the same bug one nesting level apart, and both decoded to a
**wrong build rather than an error**:

1. An action record joined its fields with `.` while its term lists joined their items with `.` too.
   Splitting the record destroyed the terms.
2. The tally bag joined its items with `-`, and the tally bag lives inside a run-length stream whose
   runs are separated by `-`. A bag defeated the run parser.

**A separator may never appear in anything it delimits.** `CODE_SEP` names one character per nesting
level for exactly this reason, and probes E and F re-introduce each bug to prove the round-trip rows
would have caught it.
</the_two_grammar_bugs>
